# TDS 참고 디자인 일관성 개선

## 기준
공식 TDS 패키지 도입이 아닌 기존 프로젝트의 자체 PC 디자인 시스템을 따른다. 기존 application-inputs.module.css의 입력·도움말·오류 스타일과 글로벌 pagehead/tabs/badge/section 스타일을 재사용한다. 변경 범위는 신규 캠페인 운영, 참여자 화면, 참여 가이드와 공통 UI이며 API·정산·추천료·일정 계산 로직은 유지한다.

## 개선 내용
- 공통 UI: Field, Button, Form, Feedback, EmptyState, StatusBadge, Tabs, useDecisionDialog.
- 주요 행동 파란 버튼, 보조 행동 중립 버튼, 지급 취소 등 위험 행동 의미색 구분.
- 공통 입력: 필수 표시, 필드별 오류, aria-invalid/aria-describedby, 잘못된 첫 필드로 포커스.
- 관리자 5탭: 견적·일정 / 모집·배정 / 검수·유지 / 참여자·정산 / 알림 이력.
- 참여자 4탭: 참여 제안 / 게시 작업 / 참여 설정 / 정산·추천. 탭 전환 시 입력 상태 보존.
- 브라우저 prompt/confirm을 접근 가능한 dialog로 교체. 수정 내용과 주요 수정 여부를 한 창에서 확인한다. Escape 취소, 포커스 복귀 지원.
- 초기 로딩, 접근 실패, 빈 목록, 저장 성공/실패 구분. 내부 상태 한글 배지 표시. 메시지 접수와 제안 수락의 상태명도 구분.
- 폼 PC 2열 / 모바일 1열, 주차별 수량은 압축 행, 긴 계정 주소 줄바꿈. PC 44px 입력, 모바일 52px 입력. 모바일 버튼 최소 48px.
- 색·간격·라운드는 공통 토큰 사용. 기존 견적·제안서 PDF 디자인은 유지.

## 검증
- 전체 테스트 72개 통과. 타입 검사 및 프로덕션 빌드 통과.
- PC 1280px/1440px, 모바일 390px/360px에서 브라우저 확인. 검사한 화면에서 가로 넘침 없음.
- 실제 UI: 필수 입력 오류 → 견적 저장/확정 → 제안 등록/수락 → 링크 제출 → 주요 수정 요청.
- 계정 권한 확인·접속 링크 재발급 다이얼로그, Escape 취소, 방향키 탭 탐색 확인.
- 콘솔 오류/경고 0건. 기존 기능은 격리 테스트 스키마에서 검증했으며 실발송 없음.
- 화면 캡처는 output/qa/design-*.png. 테스트용 서버/스키마는 확인 후 정리한다.
