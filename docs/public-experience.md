# 고객 보고·참여자 화면 개선

TDS를 참고한 원케이션 블루, 작은 보조 문구와 명확한 제목 위계, 공통 간격을 적용했다. 스타일은 공개 화면에만 한정한다.

- 고객 보고: 실제 작업 상태별 분포, 블로그·클립 게시 확인 비율, 주별 계획·접수·확인 수량을 표시한다. 콘텐츠 상세와 확정 키워드는 펼쳐서 확인한다. 취소 작업은 진행률에서 제외하며 링크 접수를 게시 확인으로 계산하지 않는다.
- 참여자: 복구 요청 → 수정 요청 → 게시할 자료 → 새 제안 순으로 다음 할 일을 안내한다. 작업 상태 필터와 자료 준비·링크 제출·게시 확인·지급 완료 단계를 추가했다. 지급 완료는 실제 지급 상태로만 표시한다.
- 기존 로그인, 파일 접근 권한, 원고 복사, 다운로드, 링크 제출, 제안 응답, 참여 설정, 정산·추천 및 고객 보고 엑셀 기능은 유지한다. 고객 공개 데이터 범위도 변경하지 않는다.

## 검증

- 타입 검사, 프로덕션 빌드, 전체 테스트 206개 통과.
- 실제 API를 사용하는 격리 QA 데이터로 PC·모바일 1440/1024/768/390/360px 가로 넘침 확인.
- 고객 상세·게시물 링크·엑셀 다운로드, 비로그인 파일 접근 차단, 원고 복사·이미지 다운로드·링크 제출 확인.
- 중복 채널 제안 수락 차단과 거절, 참여 가능 수량 저장, 추천 링크 복사 확인.
- 실제 메시지·AI 생성·송금은 실행하지 않는다. 테스트용 DB 스키마와 저장 파일은 검증 후 정리한다.

## 자료 전달·게시 제출 추가 점검

자료 저장 / 원고 복사 / 게시 후 링크 제출 구간을 짧은 레이블로 구분하고 주요 저장·복사·제출 조작에 최소 44px 높이를 적용했다. 게시 후에는 제출란으로 이동하면서 입력란에 초점을 맞추는 버튼을 제공한다. 저장 여부나 게시 완료를 임의로 기록하지 않는다.

1440/768/390/360px에서 실제 권한을 사용하는 QA 화면을 확인했다. 이미지 다운로드, 광고 표시를 포함한 원고 복사, 복사 권한 실패 시 원고 펼침·전체 선택, 제출란 이동·초점, 실제 게시물 링크 제출을 확인했다. 타입 검사·프로덕션 빌드와 관련 테스트 15개가 통과했다. 모바일 폭 검증은 데스크톱 브라우저에서 수행했으며 휴대폰 OS 저장·공유 메뉴와 네이버 앱 실행 자체는 실기기 확인 대상이다.
