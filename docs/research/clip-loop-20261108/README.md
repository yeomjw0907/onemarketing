# 2026-11-08 영상 관찰 루프와 생성 로직 개선

공개 Shorts 새 1,000개와 사용자가 제공한 MP4 5개, 총 1,005개를 대상으로 편집 관찰을 수행했다. 공개 영상의 대표 구간 2,938개를 저장했다. 정확한 개수·분야·대표 구간 수·사용량과 파일 해시는 [검증 기록](verification.json)에 있다. 기존 공개 관찰 카탈로그 1,000개와 URL 중복은 없다.

이 작업은 **영상 관찰 → 조건부 편집 가설 → 서비스 지침·검수 구현 → 회귀 검사**다. 모델 가중치 학습, 광고 성과 최적화 완료, 1,000편 전체의 사람 시청을 뜻하지 않는다.

## 관찰 범위

- 공개 후보는 44개 채널 Shorts 탭에서 새로 모은 1,800개다. 기존 카탈로그 URL을 제외하고 채널별로 순환 표집했다. 전체 Shorts의 인기 순위나 무작위 표본은 아니다.
- 성공 1,000개는 `gemini-3.1-flash-lite`에 첫 30초·1fps를 명시해 전달했다. 원본 ID, 시간 순서와 범위, 화면 접근, 필수 필드, 근거 구간 참조를 검사했다. 실패·잘린 출력은 성공 수에 넣지 않았다.
- 첨부 5개는 전체 길이를 3fps로 전달하고, 4~5초 간격의 표집 프레임을 별도로 확인했다. 영상 입력만으로 음성을 판단하지 않고, 전체 음성 트랙을 16kHz 모노·32kbps MP3로 별도 AI 분석했다. 사람 청취 검증은 없다. 전사·화자 판단·정밀 시간은 추정이며 원문 대본으로 사용하지 않았다.
- fal 대체 경로는 HTTP 403으로 거절되어 중단했다. 이 경로에서 성공으로 센 관찰은 0개다. 이후 직접 API를 사용했고, 요청 제한의 대기 시간을 반영했다.
- 원본 영상·음원·인물 컷아웃은 결과물에 재사용하지 않았고 Git에도 넣지 않았다. 첨부 파일의 절대 경로, 비밀 키, 공급사 요청 식별자는 공유 카탈로그에서 제외했다.

## 서비스에 반영한 변경

1. **유형별 편집 지침 선택:** 기능 과정·대화형·제품 세부·공간 설명을 구분한다. 촬영 대상 또는 명시적인 대화형 요청을 사용하며, 사용자 데이터 안의 임의 지시를 실행하지 않는다.
2. **관찰 근거 연결:** 작은 근거 인덱스에서 유형에 맞는 대표 원본 ID·구간을 선택해 기존 `mediaGuidance`에 전달한다. 대화형과 서비스 과정은 첨부 참고의 파일 해시·구간에 연결한다. 공개 관찰은 검토 전 가설 상태를 유지한다. 외부 모델을 추가 호출하거나 전체 카탈로그를 프롬프트에 넣지 않는다.
3. **장면별 연출 구분:** 모든 장면의 동일 카메라 문구, 누락된 위치·방향·크기·광원 연결 조건을 브리핑 검토 메모로 표시한다. 승인한 연출을 자동으로 덮어쓰지는 않는다.
4. **공통 최종 영상 검수:** `saveAsset`에서 제작 작업의 최종 `video`에 최대 60초·2fps 밝기 표집 검사를 수행한다. 중앙 80%를 64×64로 비교해 긴 변화 부족과 거의 검은 화면을 안내한다. 원본 업로드·중간 생성 재료·유료 생성 API에는 새 호출을 만들지 않는다.
5. **결과 보존과 운영 화면:** 경고 구간은 결과물 옆에 표시한다. 검사 실패는 `unavailable`로 남기며, 업로드된 유료 결과를 폐기하거나 새 생성 요청을 보내지 않는다. 픽셀 변화는 의미 있는 움직임·제품 형태·가독성의 증명이 아니다.

생성 모델이 그려야 할 장면과 후편집할 자막·음성·CTA를 계속 분리한다. 생성 사진을 움직이는 영상이라고 소개하지 않는다. 사용 허용 앱 화면이 없는 경우 사용자에게 화면녹화를 요구하는 방식으로 되돌아가지 않는다.

## 검증과 범위

다른 작업의 미완료 변경을 포함하지 않는 별도 Git 작업본에서 타입 검사, 신규 정책·실제 FFmpeg 검수·최종 파일 저장 테스트, 기존 워크플로 회귀 검사를 수행했다. 카탈로그 검사는 1,000개 URL 중복, 이전 카탈로그와 중복, 모든 관찰 구조, 인덱스의 실제 근거 구간을 검사한다. 검수 실패 시 파일 바이트가 보존되는 것도 확인했다.

빌드는 분리 작업본의 의존성 연결 경로 때문에 Turbopack이 패키지를 찾지 못해, 공식 지원되는 webpack 경로로 프로덕션 빌드를 검증했다. 새 유료 생성 영상의 전후 품질 비교나 게시 성과 실험은 이번 범위에 포함하지 않았다. Git push와 운영 배포는 별개다.
