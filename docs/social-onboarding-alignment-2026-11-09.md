# 소셜 로그인 온보딩 정렬 — 2026-11-09

## 문제와 변경

광고주는 소셜 인증 후 신규 가입/기존 계정 연결을 선택하지만 체험단은 곧바로 참여 신청서로 이동했다. 체험단 기존 계정 연결 요청 API는 존재했지만 해당 화면에서 접근하기 어려웠다. 광고주의 기존 계정 연결 성공 후에도 기본 복귀 경로가 없으면 로그인 페이지에 머물러 연결 실패로 오해할 수 있었다.

- 두 역할의 인증 완료 안내·가입/연결 선택을 공통 컴포넌트로 맞췄다. 연결된 **현재 역할의** 계정이 없다는 점과 두 역할의 가입·연결이 별개임을 명시한다.
- 카카오·구글의 미연결 체험단 인증 결과는 광고주와 동일한 로그인 온보딩 셸로 돌아온다. 신규 가입을 선택하면 기존 신청서로 이동하며 신뢰된 인증 정보·레퍼럴을 유지한다.
- 체험단 기존 계정 연결은 등록 이름·휴대폰으로 요청하고 담당자가 본인 확인 후 승인한다. 요청만으로 접근 권한이 생기지는 않는다. 기존 승인·거절·연결 철회 로직은 유지한다.
- 광고주는 기존 이메일·비밀번호 확인 후 연결한다. 로그인·신규 가입·연결 성공 후 유효한 복귀 경로나 광고주 마이페이지로 이동한다.
- 역할 버튼은 선택한 역할을 URL에도 반영한다. 두 역할의 소셜 버튼을 같은 컴포넌트로 렌더링한다. 구글 연결 버튼이 카카오 연결로 표시되던 문구도 제공자 공통 문구로 고쳤다.
- 체험단 가입 완료의 ‘바로 참여’ 표현을 실제 활동 계정 소유 확인 조건에 맞췄다.

이름/이메일 일치로 광고주와 체험단을 자동 병합하거나 다른 역할의 업무·정산 정보 접근을 부여하지 않는다. 신규 계정 생성 및 실제 고객 계정 연결을 운영 환경에서 대신 진행하지 않았다.

## 검증

관련 인증·레퍼럴·로그인 회귀 테스트 23개와 타입 검사·운영 빌드 통과. 전체 회귀는 **348개 통과, 실패 0건**이다. 첫 전체 병렬 실행은 테스트 DB session pool 15개 제한으로 3건 실패하여 통과로 취급하지 않았고, 동시 실행 4개·프로세스별 pool 1개로 재검증해 통과했다. 운영 서버리스 DB는 별도로 transaction pooling을 사용한다.

기본 마이페이지 이동은 로그인 페이지에서만 적용한다. 같은 로그인 컴포넌트를 쓰는 광고주 MCP 권한 동의 화면은 본인 확인 후 원래 동의 절차에 머물도록 유지한다. 마지막 적용 범위 조정 후 빌드·타입 검사를 다시 실행했다.

격리 스키마를 쓰는 실제 Next 운영 빌드에서 다음을 화면으로 확인했다.

1. 체험단 인증 후 공통 선택 화면 → 신규 신청서 이동 → `ref` 유지.
2. 기존 체험단 계정 확인 요청 → 접수 대기 표시. 실제 계정 자동 연결 없음.
3. 광고주 동일 선택 화면 → 기존 이메일·비밀번호 확인 → 기존 광고주 계정 연결 → `/advertisers` 업무 화면 도착.

증거는 ignored `output/onboarding-*.png`, `output/onboarding-tests.log`, `output/onboarding-build-final.log`, `output/onboarding-all-tests-bounded.log`에 있다. 테스트 계정·더미 인증 정보는 운영과 분리하고 실제 문자·송금·새 OAuth 제공자 권한 부여 없이 검증했다.

## 남은 운영 설정

사용자가 제공한 수취 계좌는 아직 등록 완료로 확인하지 않았다. 관리자 브라우저에서 인증 세션이 확인되어야 등록을 이어갈 수 있다. 계좌번호를 Git 파일에 저장하지 않았다. 해당 실제 계정의 신규 가입/기존 계정 연결은 수행하지 않았다.

## 운영 배포 후 실제 카카오 확인

`2930191`의 Vercel 운영 배포 READY 및 `www.onemarketing.kr` 연결을 확인했다. 실제 사용자 카카오 계정은 광고주와는 미연결이지만 **기존 체험단과는 정상 연결되어 있었다.** 운영 체험단 로그인 → 본인의 나의 작업 표시 → 로그아웃 후 개인정보 대신 로그인 버튼 표시 → 카카오 재로그인 → 같은 체험단의 `내 캠페인 지원` 탭 복귀까지 확인했다. 신규 계정이나 실주문은 만들지 않았다. 광고주 미연결과 체험단 매칭을 구분해야 하며, 두 역할 전체가 매칭에 실패한 상황은 아니었다.

운영 주요 HTTP·MCP 메타데이터 200, 익명 MCP 401, 광고주 MCP 잘못된 Origin GET/POST 403도 재확인했다. 현재 체험단은 활동 계정 소유 확인 안내가 표시되므로 실제 캠페인 지원을 위한 소유 확인은 별도 필요하다.
