# 광고 상품·체험단 공개 모집 운영

## 진입 화면

- `/marketing`: 광고주용 상품 목록·상세·수량 선택·신청.
- `/advertisers`: 광고주 회원가입·로그인·내 신청·견적·진행 상태·확인된 게시 결과.
- `/campaigns`: 공개 모집 검색·채널 필터·조건 확인·활동 계정 선택·지원·내 지원 현황.
- 기존 관리자 화면의 **상품·모집 플랫폼**: 상품 공개, 광고 신청 접수, 모집 공개, 지원자 선정.
- 체험단 **나의 작업 → 내 캠페인 지원**: 지원 상태 확인·선정 전 철회. 선정 후 기존 참여 제안에서 조건을 수락한다.

## 처음 공개할 때

운영 가격이나 내부 프로젝트는 자동 공개하지 않는다. 관리자에서 실제 판매할 상품과 모집할 캠페인을 명시적으로 게시한다.

1. 기존 단가 관리에서 블로그(이미지 3장)·클립(10초 생성형)의 판매 단가를 확인한다.
2. 상품·모집 플랫폼 → 공개 상품 관리 → 상품 등록에서 제목·설명·상품 유형·단가·제공 범위·일정·수정 조건을 입력한다.
3. `외부 상품 목록에 공개`를 선택해 저장하고 `/marketing`에서 확인한다. 원가·게시자 보수·마진은 공개하지 않는다. 판매가는 VAT 별도로 표시하고 신청 합계에는 VAT 10%를 반영한다.
4. 광고 신청 접수 후 기존 고객·제품을 선택하거나 신규 생성하여 견적 초안으로 전환한다.
5. 기존 캠페인 운영의 견적 검토·확정 절차를 진행하면 계약과 작업 슬롯이 생성된다. 접수는 결제 완료나 제작 시작을 의미하지 않는다. 실제 결제/입금 확인은 기존 운영 절차에서 처리한다.
6. 공개 캠페인 모집에서 해당 프로젝트를 선택하고 공개용 제목·설명·가이드·마감일을 입력하여 게시한다.

## 광고 신청 처리

광고주는 별도 이메일·비밀번호 계정을 사용한다. 관리자·체험단 세션과 분리되며 본인 계정의 신청만 조회한다. 회원가입과 신청에서 개인정보 수집 동의를 받는다. 비밀번호는 scrypt 해시, 세션은 해시로 저장하며 로그인 시도는 제한한다.

신청 당시 상품 구성·판매가·수량·조건을 저장하고 서버에서 금액을 계산한다. 같은 요청 ID의 재전송은 같은 신청으로 처리한다. 상품이나 가격이 조회 후 변경되면 재확인을 요구한다. 접수 이후 단가가 바뀌어 견적 금액이 달라지면 견적 전환을 롤백하고 광고주와 금액을 확인하도록 안내한다.

고객 연결은 운영자가 명시적으로 수행한다. 같은 업체명이나 이메일만으로 기존 고객에 자동 연결하지 않는다. 하나의 광고주 계정은 하나의 고객에 연결하며 다른 계정이 연결된 고객의 권한을 가져오지 못한다. 제품은 선택한 고객에 속해야 한다. 내 진행 내역은 해당 신청에서 전환된 견적·프로젝트만 조회하며 다른 고객의 프로젝트를 합쳐 노출하지 않는다.

## 공개 지원과 추천 제안

공개 지원은 별도 원장에 남고 정원을 예약하지 않는다. 운영자가 선정할 때 기존 `proposeWork`로 실제 남은 슬롯에 제안을 생성한다. 이때 계정 승인·소유 권한 확인·프로젝트 진행 상태·중복 제안 검사를 그대로 적용한다. 회원이 기존 `respondOffer`에서 수락해야 최종 배정된다.

진행 중인 추천 제안이 예약한 슬롯은 공개 모집의 남은 수에서 제외된다. 제안이 만료되면 다시 모집 가능 수에 포함된다. 선정과 추천 제안 생성은 같은 프로젝트 잠금 안에서 처리하므로 마지막 한 자리를 두 회원에게 동시에 예약하지 않는다.

공개 지원은 회원·캠페인당 한 건이며 철회 후 다시 지원할 수 있다. 기존 활성 제안이나 배정이 있으면 해당 제안을 확인하도록 안내한다. 보류·취소·완료·정산 마감·게시 기한 종료 또는 비공개 캠페인에는 신규 지원할 수 없다. 모집 기한이 지나도 이미 받은 지원자는 프로젝트 진행 가능 기간 안에서 선정할 수 있다.

기본 원고료는 목록에 안내하고 개별 약정은 최종 제안에서 확정한다. 블로그 3,000원·클립 3,000원·묶음 7,000원 기본값과 기존 프로필 약정액 적용을 유지한다. 지원·선정만으로 원고료나 추천 보상이 발생하지 않는다. 첫 정상 캠페인 원고료 지급 시 특별 추천 보상 2,000원, 기존 단독 500원·묶음 1,200원 규칙을 그대로 사용한다.

## 배포·검증

`20261023020000_public_market.sql` 마이그레이션이 필요하다. 새 테이블은 RLS를 켜고 anon/authenticated 직접 접근을 차단한다. 기존 업무 레코드 형식은 변경하지 않는다.

- `tests/market.test.ts`: 계정·세션, 공개 정보 범위, 신청 금액·중복, 견적 전환/롤백, 공개 지원·철회·선정·수락, 정원 경쟁, 보류·비공개 제약.
- 기존 추천 보상·워크플로우 회귀 테스트.
- `npm run typecheck`, `npm run build`, 프로덕션 의존성 보안 감사.
- `npx tsx scripts/market-acceptance.ts`: 임시 acceptance 스키마와 로컬 전용 계정으로 브라우저 검증. 운영 데이터에는 테스트 상품·캠페인·계정을 만들지 않는다. 종료 시 임시 스키마를 삭제한다.

테스트 서버 기본 주소는 `http://127.0.0.1:3120`이며 QA 전용 관리자 `market-qa@local.test` / `market-qa-password`를 사용한다. 스크립트는 해당 프로세스의 관리자 설정만 덮어쓰고 모집 알림 발송을 비활성화한다. 운영 계정이 아니다.
