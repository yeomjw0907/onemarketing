# 홈페이지·플랫폼 흐름 및 색인 재점검

## 실제 색인 확인

- Google Search Console에서 `/about`, `/marketing` 모두 **URL이 Google에 등록되어 있음 / 페이지 색인이 생성됨** 확인. 실제 색인 상태이며 재수집 요청 접수와 구분한다.
- 네이버 서치어드바이저의 색인 상태 확인에서는 두 URL 모두 수집 데이터가 없어 검사 결과가 제공되지 않음. 따라서 네이버 색인 완료로 보고하지 않는다.
- 네이버 사이트맵 등록, 주요 페이지 수집 요청 및 홈페이지 robots 수집 허용은 이전 점검에서 확인됨. 두 공개 URL의 200 응답·canonical·index·본문 서버 렌더링과 인증 태그를 재확인한다.
- 네이버 공식 [수집 안내](https://searchadvisor.naver.com/guide/request-crawl)는 수집 요청이 실시간 방문이 아니며 최소 1일에서 수 주가 걸릴 수 있다고 설명한다. 반복 제출이나 내용 없는 메타데이터 변경으로 해결되는 문제로 취급하지 않는다.

## 발견한 문제와 이번 수정

1. 홈의 대표 행동이 ‘서비스 알아보기’에 머물러 광고주와 참여자가 어디서 시작할지 불명확했다. **체험단 모집하기 / 캠페인 참여하기**를 첫 화면에 배치하고 소개 링크도 유지했다.
2. 기존 이용자가 업무 화면으로 돌아가는 경로가 부족했다. **내 참여·리워드 / 광고주 캠페인 관리 / 이용 가이드** 바로가기를 추가했다. 각 링크는 기존 인증·접근 권한을 그대로 사용한다.
3. 점검 시 운영 공개 캠페인이 0개였다. 쓸 수 없는 검색·필터·반복 0개 카운터가 화면을 채우고, 빈 화면의 다음 행동도 광고주 등록만 제시했다. 홈에서 공개 목록이 비었음이 확인된 경우 해당 컨트롤을 접고 **참여자 시작·참여 방법**을 안내한다. 데이터가 로딩 중이거나 오류인 경우와 구분하며, 캠페인이 있으면 기존 검색·필터를 표시한다.
4. `role=participant&signup=1` 링크의 명시적 참여자 역할이 일반 가입 플래그에 덮여 광고주 화면이 열렸다. 명시적 역할을 우선하도록 수정했다. 이 역할 선택은 화면 진입만 결정하며, 인증·서버 권한은 변경하지 않는다.

## 검증

- 명시적 참여자 가입, 광고주 진입, 기존 캠페인·상품 기본 진입 경로 단위 테스트.
- 공개 SEO 설정 및 카카오·구글 추천인 가입·재로그인 회귀 테스트.
- 격리 DB 환경에서 빈 목록, 공개 캠페인 존재, 검색 결과 0개, 조건 초기화 후 결과 복원, 참여자 가입 이동, 캠페인 목록 앵커 이동 확인.
- 390px 모바일 및 데스크톱에서 버튼 표시·화면 가로 넘침 확인.
- TypeScript와 프로덕션 빌드, 배포 후 실제 공개 URL 응답 재검사.
- 검증 캠페인은 별도 `lifecycle_*` 테스트 스키마에만 생성하며 운영 캠페인이나 결제를 생성하지 않는다.

## 플랫폼으로 성장하기 위해 남은 우선순위

**가장 시급한 것은 실제 캠페인 공급이다.** 점검 시 공개 캠페인이 0개여서 탐색→지원→선정→게시→정산의 경험을 신규 이용자가 시작할 수 없었다. 임의 캠페인·고객 수·후기를 추가하지 않았다. 실제 광고주의 승인된 캠페인을 확보하고 조건·마감일·보상 정보를 명확히 공개하는 운영 작업이 필요하다.

그다음은 다음 세 가지를 제품 기록에 근거해 운영하는 것이다. 이번 변경에서 신규 기능을 구현했다고 주장하지 않는다.

- **완료 경험과 신뢰:** 실제 게시 확인·정산 완료 사례를 당사자 허락과 확인 가능한 결과에 근거해 소개한다. 활동 실적이 확보된 뒤 수치·후기를 사용한다.
- **반복 이용:** 역할별 대시보드의 다음 할 일, 제출·검수·정산 상태, 재참여 경로를 연결한다. 이번 홈 바로가기는 기존 업무 화면의 접근성을 개선한 첫 단계다.
- **공급과 참여의 균형 측정:** 공개 캠페인 조회→가입→지원/주문→선정→게시 승인→정산→재참여를 각각 측정한다. 가입자 수만으로 플랫폼 성과를 판단하지 않는다. 기존 기록과 실제 측정 가능 범위를 먼저 확인하며 이번 작업에서 외부 추적 SDK를 설치하지 않았다.
