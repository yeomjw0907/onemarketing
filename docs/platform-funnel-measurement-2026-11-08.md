# 가입·첫 행동·완료·정산 측정

관리자 진입: `/admin/platform/analytics`. 주문·캠페인 운영과 상품·모집 플랫폼 화면에 링크를 추가했다. 관리자 페이지와 집계 API 모두 관리자 세션을 검사하고 응답을 `private, no-store`로 제공한다.

## 질문과 집계 기준

| 확인할 질문 | 시작 단위 | 실제 기록으로 확인하는 단계 |
| --- | --- | --- |
| 참여자가 가입 후 지원하는가? | 공개 가입 신청자 | 신청 접수 → 참여자 등록 → 첫 캠페인 지원(기존/새 모집 모두) |
| 광고주가 가입 후 주문하는가? | 생성된 광고주 계정 | 계정 생성 → 새 주문 시스템 첫 주문 |
| 지원 후 어느 단계에서 멈추는가? | 새 캠페인 지원건 | 접수 → 수락 → 게시 링크 제출 → 검수 승인 → 리워드 지급 |
| 주문이 운영 완료로 이어지는가? | 새 주문건 | 접수 → 입금 확인 → 해당 주문의 모든 캠페인 완료 |
| 기존 모집의 작업도 지급까지 이어지는가? | 기존 모집 지원건 | 접수 → 연결된 배정 수락 → 배정의 모든 게시 제출 → 모든 검수 승인 → 전체 지급 |

- 날짜는 한국 시간의 시작일~종료일(양끝 포함), 최대 366일이다. 각 시작 시각부터 7/30/60일 중 선택한 기간 내의 순차 도달을 계산한다.
- 관찰 기간이 끝난 집단만 전환율에 포함한다. 분자는 같은 집단·같은 마감 시각의 도달 수이고 분모는 그 이전 단계의 도달 수다. 분모가 0이면 비율을 표시하지 않는다.
- 현재 누적 도달 수는 관찰 중인 건도 포함하고 관찰 마감 이후 도달도 포함하므로 확정 집단의 전환율과 구분한다. 현재 상태 분포 역시 전체 조회 집단 기준이다.
- ‘기간 내 미도달’은 영구 이탈이나 사용자의 잘못을 뜻하지 않는다. 선정/검수/지급 대기, 캠페인 공급 부족, 거절·철회·취소를 함께 확인해야 한다. 철회·취소는 분모에 남긴다.
- 지원/주문 ID 기준으로 중복을 제거한다. 여러 캠페인의 가입·지원·지급을 섞지 않고 같은 지원건·주문건에 연결한다. 최초 제출 시각은 재제출로 덮어쓰지 않는다. 수락·운영 완료 시각도 앞으로 실제 저장 시 기록한다.
- 소요 시간은 확정 집단 중 기간 내 전환된 건의 이전 단계 대비 중앙값이다.

## 범위와 한계

기존 견적 상담은 새 결제 주문으로 간주하지 않으며 해당 건수를 따로 표시한다. 관리자 직접 등록 참여자는 공개 가입 코호트에서 제외한다. 광고주 계정 코호트는 계정 생성 기준으로 관리자 발급 계정도 포함한다. 캠페인은 미리보기 기록을 포함한 업무 DB 기준이므로 테스트 운영 기록이 존재할 수 있다. 실제 영업 성과라고 단정하지 않는다.

기존 모집은 지원에 연결된 제안/배정과 그 배정의 작업만 사용한다. 연결 정보가 없거나 일부 게시 작업의 시각이 없으면 확인 가능한 단계까지만 센다. 직접 배정되어 공개 지원 기록이 없는 작업은 공개 지원 퍼널에 포함하지 않는다. 부분 지급만으로 전체 정산 완료를 세지 않는다.

과거 시각이 없으면 `updated_at`으로 추정하지 않는다. 새 캠페인의 과거 제출은 마지막 제출 시각만 존재할 수 있어 최초 도달보다 낮게 잡힐 수 있다. 완료 시각이 없는 과거 캠페인 수와 중간 시각이 누락/역전된 건을 표시한다. 가입 화면을 열고 제출하지 않은 방문, OAuth 동의 화면에서 중단한 방문은 이 집계 범위가 아니다.

기존 PostgreSQL 업무 기록을 읽기 전용 트랜잭션의 일관된 스냅샷으로 집계한다. 신규 외부 분석 서비스·추적 쿠키·환경변수·DB 마이그레이션은 추가하지 않았다. API는 집계 수치/상태만 반환하며 이름·연락처·게시 URL·계좌·자유 입력·소셜 식별자·개별 사용자 ID를 내보내지 않는다. 클릭이나 제출 시도를 성공으로 세지 않는다.

## 함께 수정한 흐름

1. 입금 완료/취소 주문에 입금을 다시 안내하지 않는다. 입금한 사용자는 중복 결제 대신 확인 대기를 안내받고, 입금 완료 주문에서 해당 캠페인 진행 화면으로 이동할 수 있다.
2. 지원 접수/검수 대기/검수 승인 후 지급 대기를 구분해 다음 행동과 정산 문의 경로를 안내한다. 거절·만료·철회 후에는 다른 캠페인을 찾을 수 있다.
3. 제출 입력의 `blog/clip` 대신 블로그/클립 명칭을 표시한다.

## 검증과 운영 기준

- 전체 회귀 테스트 336개 통과. 최종 집계/기존 주문·정산 관련 12개를 추가 재실행하여 통과했다. 타입 검사와 운영 빌드를 수행했다.
- 격리 DB의 실제 가입·주문·지원·작업 기록으로 집계 도착을 확인했다. 최근 관찰 중 계정은 분모에서 제외되고, 종료 집단 2계정 중 첫 주문 1건은 50%로 계산됨을 HTTP와 브라우저에서 대조했다.
- 잘못된 날짜·관찰 기간, 중복, 취소, 관찰 경계, 누락/역전 시각, 전체 캠페인 완료 조건, 기존 모집의 일부 작업 미완료 조건을 검증했다.
- 익명/참여자 세션의 API 접근은 401, 관리자 세션은 200, 잘못된 조회 조건은 400을 확인했다. 개인정보가 집계 응답에 없는 것도 검사했다.
- 운영 DB는 읽기 전용으로 대조했다. 2026-11-08 기준 최근 90일 조회에서 공개 가입 신청 6명, 광고주 계정 3개가 모두 30일 관찰 중이었다. 확정 전환율이나 개선 효과를 단정할 표본은 아직 없다.

다음 운영 점검은 첫 지원·주문의 미도달 건수와 선정·검수·지급 대기 상태를 함께 보며 우선순위를 정한다. 표본이 축적되기 전에는 전환율 상승을 성과로 주장하지 않는다.
