# 고객 질문 흐름과 제품 자료실

- 광고주 회원가입은 사업자 유형 → 업체/브랜드 → 업종/소개 → 지역/링크 → 담당자/로그인 정보 → 동의 → 전체 확인 순서입니다. 개인·창업 준비 중이면 사업자번호를 생략하고 카카오 인증을 마쳤으면 비밀번호를 묻지 않습니다.
- 좌측 화살표는 이전 질문으로 이동하며 작성 내용은 유지합니다. 첫 단계에서 비활성화됩니다. 선택 질문은 다음으로 건너뛸 수 있고 마지막 확인 화면에서 각 답변을 수정할 수 있습니다. 비밀번호는 확인 화면에 노출하지 않습니다.
- 관리자 프로젝트의 자료 탭에서 회사, 제품, 캠페인 조건·일정, 파일, 링크 중 필요한 범위로 전용 링크를 발급합니다. 고객은 방문/배송/자료 제작 방식에 해당하는 질문만 보며 다음 단계마다 서버에 임시 저장합니다.
- 링크 토큰은 URL fragment로 받아 브라우저 기록에서 제거하고 HttpOnly 쿠키로 교환합니다. 쓰기 요청은 intakeId를 함께 검증해 다른 탭에서 연 캠페인의 쿠키와 섞이지 않게 합니다. 만료·회수·종료된 프로젝트는 접수가 차단됩니다.
- 제출본은 revision으로 보관하고 관리자 확인 후 캠페인 source 자료로 반영합니다. 보완 요청 시 같은 링크로 다시 작성할 수 있습니다. 고객 답변이 제품 마스터를 자동 덮어쓰지는 않습니다.
- 광고주 마이페이지 ‘내 제품·서비스’에서 자신의 고객에 속한 제품을 조회·등록·수정하고 제품별 자료를 추가·다운로드합니다. 관리자 고객의 제품 목록 및 자료실에서도 동일한 레코드를 확인합니다. 내부 메모와 저장소 키는 고객 응답에 포함하지 않습니다.
- 제품을 수정하기 전 기존 프로젝트에 당시 제품 마스터를 스냅샷으로 보관합니다. 기존 캠페인 제작 기준과 승인 상태를 유지하며, 이후 새 캠페인은 최신 제품 정보를 사용합니다. 제품 자료 추가는 기존 캠페인에 자동 투입하지 않습니다. 관리자가 필요한 파일을 캠페인으로 복사할 수 있습니다.
- 제품 자료는 파일당 4MB, 제품별 30개까지이며 이미지/PDF/XLSX/CSV/텍스트를 지원합니다. 큰 영상은 공유 링크로 전달합니다. 캠페인 링크는 서명 업로드로 MP4 40MB까지 지원합니다.

## 검증

DB 테스트는 임시 스키마 및 Storage 접두어를 사용합니다. 소유권, 변조, 버전 충돌, 제품 기준 스냅샷, 파일 다운로드 격리, 링크 임시 저장/제출/보완/승인/회수를 검증합니다. Playwright에서 회원가입의 이전 단계 복귀·조건부 질문·비밀번호 마스킹, 캠페인 질문별 임시 저장과 제출, 제품 수정·자료 추가의 모바일/데스크톱 화면을 검증합니다. UI 검증은 응답 모의 처리로 운영 고객 데이터를 생성하지 않습니다. 별도의 임시 DB/Storage를 사용하는 실제 production 서버 HTTP 검사에서 가입·파일 업로드/다운로드·고객 간 격리·CSRF·다중 탭 캠페인 혼선 차단·관리자 승인을 검증했습니다.

배포 전 `20261028010000_customer_intake.sql`을 적용합니다. 기존 workflow_items 테이블이 있으면 구조를 유지하는 멱등 migration입니다.
