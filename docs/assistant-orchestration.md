# 채팅에서 자료 접수부터 제작·전달까지

## 사용 흐름

1. 업무 도우미에서 회사·제품 자료를 첨부하고 필요한 일을 자연어로 요청한다. 파일은 대화에만 저장된다.
2. 확인된 내용을 정리하고 누락된 정보만 질문한다. 고객·제품·캠페인 초안은 기존 확인 카드에서 저장한다.
3. 고객 또는 프로젝트에 자료를 등록할 때 파일명과 대상을 확인한다. 첨부만으로 기존 자료실에 자동 등록하지 않는다.
4. 견적·계약 확정 카드는 견적서와 프로젝트 설명서를 열어 검토한 뒤 체크하고 확정한다. 기존 확정 함수로 프로젝트·게시 작업을 생성한다.
5. 제품 정리·제품 정보 확정·키워드 조사·키워드 확정·작업별 기획안·기획 승인·시나리오·브리핑·원고·이미지·영상 제작을 현재 단계에 맞춰 제안한다.
6. 확인 카드에는 작업 대상과 수량, 서버에서 계산한 예상 제작비, 제작비 상한과 사용·예약액, 외부 전달 여부를 표시한다. 체크한 단계만 실행한다.
7. 실행 후 작업 상태, 프로젝트 진행 단계, 결과물 링크를 채팅에서 확인한다. **다음 단계 준비하기**를 누르거나 자유롭게 입력해 이어간다.
8. 결과물·시나리오·생성 브리핑 승인 전 실제 내용과 파일을 검토한다. 참여자 제안·자료 전달·수정 요청도 수신 대상과 알림 내용 확인 후 실행한다.

## 지원 범위

- PDF, XLSX, CSV, TXT, MD, PNG, JPG/JPEG, WebP. 파일당 4MB, 메시지당 최대 6개, 대화당 20개.
- PDF 텍스트는 앞 30쪽과 최대 50,000자까지 추출한다. 텍스트가 없는 스캔 PDF는 원본을 보관하고 제한을 표시한다. 프로젝트 등록 후 기존 제품 정보 정리 작업으로 검토할 수 있다.
- 메시지에 포함된 첨부 중 최근 12개에서 총 60,000자 범위로 참고하고, 이미지는 최근 최대 4장을 크기 조정해 PC 모델에 전달한다. 추출 범위와 판독 한계를 숨기지 않는다.
- PPT/HWP/DOCX 등은 현재 직접 읽지 않으므로 PDF로 변환한다.
- 기존 MCP의 외부 OAuth 도구 목록과 권한은 확장하지 않았다. 제작 실행은 로그인한 관리자 대시보드의 소유자별 확인 카드로만 가능하다.

## 실행 경계

`run_workflow`는 명시된 허용 목록과 엄격한 스키마만 받는다. SQL·셸·임의 API·사용자 지정 발송 도구를 모델에 제공하지 않는다. 첨부 문서나 이전 데이터에 적힌 지시문은 승인으로 취급하지 않는다.

미리보기는 기존 DB 전용 업무 함수를 트랜잭션에서 실행한 뒤 반드시 롤백해 검증한다. 계약·작업 큐·알림 큐·감사 기록·명령 중복 방지 키는 미리보기에서 저장되지 않는다. 파일 복사와 Storage 업로드는 이 미리보기 경로에서 실행하지 않는다. 실제 확인 시 프로젝트 상태와 관련 기록의 지문을 다시 비교한다. 원래 작업 함수의 상태·예산·중복 실행·승인 브리핑·원고 품질·수신 동의 조건을 그대로 적용한다.

유료 제작비는 기존 Anthropic/fal 등 제작 서비스의 비용이다. PC 구독 채팅 연결과 별개이며 카드에 예상 비용을 표시한다. 작업 등록 후 기존 실행기를 사용하고 실제 비용은 원래 비용 원장에 기록한다. 외부 전달은 기존 알림 큐와 발송 설정을 따르므로 확인 전에는 큐에도 들어가지 않는다.

첨부는 별도 `assistant_attachments` 테이블과 비공개 Storage에 보관하고 RLS 및 관리자·대화 소유권을 검사한다. 일반 자료실/API나 고객·참여자 화면에는 보이지 않는다. 확인 후 복사된 자료만 기존 프로젝트 처리 규칙을 따른다.

## 검증

파일 소유권·형식·PDF/엑셀 추출·이미지 전달·확인 전 미등록·체크 없는 실행 거부·재시도 중복 방지·기존 승인/예산 조건·변경된 카드 차단·알림 미리보기 롤백을 테스트한다. 브라우저 검수는 일회용 DB·Storage에서 진행하고 실제 유료 공급사 호출이나 카카오 발송은 수행하지 않는다.
