# 공개 플랫폼 운영·검증

## 화면

| 역할 | 주소 | 업무 |
| --- | --- | --- |
| 공통 | `/`, `/signup`, `/login`, `/marketing`, `/campaigns`, `/ai`, `/policy` | 서비스·역할 선택, 상품 구성·장바구니, 캠페인 탐색, 이용 안내 |
| 광고주 | `/advertisers` | 주문·입금 안내, 캠페인 현황, 지원자 선정·CSV, 자료 전달, 검수, 문의·일정 연장, 부분 환불 요청 |

| 관리자 | `/admin/platform` | 입금 확인, 계좌 설정, 대행 선정·검수, 제작 프로젝트 연결, 항목별 수행금액, 미달 정산·환불 승인·송금 기록, 지급 증빙 |
| 관리자 | `/admin` | 기존 고객·제품·AI 제작·회원 승인·추천 보상·정산 |

새 상거래는 `commerce_*`, 광고주 키는 `advertiser_api_keys`, 광고주 OAuth는 `advertiser_oauth`를 사용한다. 관리자 OAuth와 참여자 인증은 독립적이다. 기존 데이터는 삭제하거나 초기화하지 않았다.

## 금액과 결제

- 모든 장바구니 금액은 VAT 포함. 기존 패키지만 공급가 200,000원과 VAT 20,000원을 함께 표시한다.
- 현금 셀프는 보수 예산 + 10% 운영비(최소 5,000원), 제품형은 1명당 3,000원(최소 5,000원). 제품·배송 비용은 별도다.
- 대행은 5명까지 60,000원, 추가 1명당 10,000원. 패키지에 셀프 운영비를 중복 부과하지 않는다.
- 계좌가 설정·활성화되지 않으면 주문을 받지 않는다. 광고주 주문은 입금 대기이며 관리자 실제 입금 확인 이후 모집이 열린다. 카드 PG·자동 송금은 포함하지 않았다.
- 실제 보수·환불 송금 후 거래 증빙을 기록해야 한다. 버튼은 은행 이체를 실행하지 않는다. 중복 지급 기록·중복 환불 기록은 차단한다.
- 캠페인별 가격·정책·동의·지급 보수·추천인을 저장한다. 같은 요청 UUID 재시도는 같은 주문을 반환하며 금액·소유권 변조는 거절한다.

## 패키지 제작

1. 기존 `/admin`에서 고객·제품·제작 프로젝트를 준비하고 기존 AI 제작 절차로 제작·검수한다. 실제 AI 호출에는 기존 모델 키·작업자 설정이 필요하다.
2. `/admin/platform`의 해당 캠페인에서 고객이 일치하는 제작 프로젝트를 연결한다. 최초 연결 시 기존 광고주 고객 연결이 없으면 관리자 확인한 프로젝트 고객과 연결한다.
3. 참여자 제안 또는 수락 후, 참여자별로 승인한 현재 제작 파일을 선택하고 원고·외부 HTTPS 링크를 전달한다. 선택한 파일만 해당 참여자와 광고주가 인증 후 다운로드할 수 있다. 원고 파일은 게시용 문구로 정리해 전달한다.
4. 연결한 기존 제작 프로젝트에서는 별도 체험단 배정·지급을 차단한다. 새 공개 캠페인에서 선정·제출·검수·지급을 처리한다. 이미 배정·제안 중인 프로젝트는 연결할 수 없다.

## 선정·일정·환불

- 조기 선정은 가능하지만 선정만으로 참여가 확정되지 않는다. 체험단이 48시간 이내에 수락하며 제출 마감까지 최소 하루를 남긴다.
- 정원은 제안 중·참여 중·완료 인원을 함께 세고 캠페인별 DB 잠금으로 동시 선정을 막는다. 만료 제안은 자동 해제한다.
- 기존 `/api/jobs/run` 인증 Cron에서 모집 마감 시 선정 단계로 전환하고 제출 48시간 전 알림을 기존 알림 발송 대기열에 등록한다. 실제 발송은 기존 SENS 활성화·템플릿·인증 설정이 필요하다. 사용자 대신 자동 선정·참여 수락은 하지 않는다.
- 기본형은 광고주가 선정·검수한다. 대행형에서는 담당자가 처리하며 광고주는 문의를 남길 수 있다. 기본 수정 1회, 추가 수정은 담당자 합의가 필요하다.
- 광고주 일정 연장은 1회. 기존 마감을 앞당길 수 없다. 대행 일정·추가 변경은 담당자가 근거와 함께 기록한다. 이전·변경 일정도 저장한다.
- 셀프 정산은 완료 인원으로 보수·운영비를 확정하고 미사용액을 환불 승인한다. 완료 0명일 때 셀프 운영비도 0원이다.
- 패키지 배분은 모집 33,000원, 영상 110,000원, 블로그 소재 44,000원, 배포 33,000원이다. 이 배분은 환불 검토의 항목 한도이며 자동 전액 차감하지 않는다. 실제 수행액·근거를 관리자 기록 후 잔액을 승인한다. 대행도 수행 근거가 필요하다.
- 참여 중인 작업은 합의·종료를 해결한 뒤 환불한다. 부분 수행 보상은 별도 합의가 필요하며 자동으로 보수를 없애지 않는다. 환불 승인은 실제 송금 완료와 구분한다.

## MCP·OAuth

서버 주소는 `APP_URL + /api/advertiser-mcp`. 상품 조회·서버 견적·본인 캠페인 조회·동의 후 주문 접수만 제공한다. 결제 확인·송금·관리자 조작 도구는 없다.

- OAuth: 광고주 로그인·동의, PKCE S256, resource 검증, 1회용 코드, 1시간 access token, 회전 refresh token, 90일 연결 만료, refresh 재사용 시 전체 연결 해제. 조회 권한과 주문 권한을 분리한다. 관리자 토큰·광고주 토큰은 교차 사용되지 않는다.
- 발견 문서: `/.well-known/oauth-protected-resource/api/advertiser-mcp`, `/.well-known/oauth-authorization-server/advertiser`. issuer는 `APP_URL + /advertiser`이고 동의·거절 응답에 같은 `iss`를 반환한다.
- ChatGPT 콜백과 로컬 개발 콜백을 지원한다. Claude 등 다른 클라이언트는 설정 화면의 **정확한 HTTPS 콜백**을 `ADVERTISER_MCP_REDIRECT_URIS`에 추가한다. 도메인·콜백을 추측하거나 광범위 와일드카드를 쓰지 않는다.
- 키 연결은 Bearer 헤더 설정 가능한 MCP 클라이언트용이다. 키는 1회만 표시하고 해시 저장하며 최대 5개·90일 만료다.
- Skill은 `/skills/onemarketing/SKILL.md`에서 제공하며 MCP 인증을 대체하지 않는다.
- 실제 ChatGPT·Claude 계정의 플랜·관리자 설정과 HTTPS 운영 도메인을 통한 연결 검증은 각 외부 계정에서 필요하다. 이 저장소 검증은 로컬 MCP/OAuth 프로토콜 통합 검증이다.

인증 구현 참고: [OpenAI 공식 MCP 인증 문서](https://developers.openai.com/plugins/build/auth#mcp-authorization-spec-requirements).

## 출시 순서

1. 배포 대상 DB를 확인하고 두 신규 migration `20261023030000_commerce.sql`, `20261023040000_advertiser_oauth.sql`을 적용한다. 전체 migrations는 `npm run db:migrate`로 이력 관리한다. 기존 운영 migration 이력이 다른 경우 신규 두 파일만 별도 검토해 적용한다. 운영 데이터 삭제는 필요 없다.
2. 배포 환경의 `APP_URL`을 실제 사이트 원점과 일치시킨다. 프리뷰는 테스트용 DB 스키마·파일 접두어와 알림 비활성화를 사용한다. 운영 DB를 테스트 데이터로 채우지 않는다.
3. 기존 관리자 계정, 참여자 휴대전화/카카오 인증, AI 공급자·작업 실행 환경, Cron과 SENS 설정을 확인한다. 추가 OAuth 콜백이 필요한 클라이언트를 등록한다.
4. 관리자 계좌 설정에서 사업자 수취 계좌를 확인한 뒤 활성화한다. 사업자·연락처·정식 약관·개인정보 문서는 실제 운영 정보로 최종 확정한다. 임의 사업자 정보는 넣지 않았다.
5. 소액 실제 주문으로 입금 확인·캠페인 공개·실제 보수 및 환불 송금·증빙까지 점검한다. 코드 푸시와 공개 배포·외부 계정 연결 검증은 구분한다.

## 반복 검증

```powershell
npm run typecheck
npx tsx --test --test-concurrency=3 tests/*.test.ts
npm run build
npx tsx scripts/platform-acceptance.ts
```

테스트는 임시 스키마를 생성·삭제한다. `platform-acceptance.ts`는 격리 HTTP 서버에서 역할별 주문·입금·지원·수락·제출·검수·미달 환불·MCP·OAuth 흐름과 페이지 응답을 확인한다. `PLATFORM_KEEP_SERVER=1`이면 브라우저 확인을 위해 `http://127.0.0.1:3109`를 유지하고 종료 시 임시 스키마를 정리한다. 테스트에는 실제 송금·외부 AI 생성·문자 발송을 포함하지 않는다.
