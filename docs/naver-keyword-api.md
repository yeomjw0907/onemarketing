# NAVER API HUB 키워드 데이터

검색광고 API는 사용하지 않는다. 서버의 `NAVER_API_HUB_CLIENT_ID`, `NAVER_API_HUB_CLIENT_SECRET`에 NAVER API HUB Application 인증을 등록한다. Application에서 블로그·검색어 트렌드 사용 권한이 필요하다. `NAVER_KEYWORD_METRICS_ENABLED=true`이면 제품 확인 후 조사·기획 생성 작업에서 추천을 만든 뒤 네이버 데이터를 함께 수집한다. 기존 분석은 기획 탭의 ‘네이버 블로그·트렌드 데이터 조회’로 갱신할 수 있다. 브라우저나 저장된 분석에는 인증키를 포함하지 않는다.

핵심·보조 순으로 중복을 제거한 최대 5개 키워드를 조회한다. 블로그는 최신순 최대 3페이지·300개를 확인하여 한국 날짜 기준 어제까지 30일 동안의 고유 URL 수를 센다. 오늘 글은 제외한다. 누적 `total`은 블로그 검색 결과 수이며 전체 발행수와 동일시하지 않는다. 표본 제한에 도달하면 최근 건수를 ‘이상’으로 표시한다. 검색색인 누락·변경 때문에 전체 최근 발행수로 단정하지 않고 관측 건수로 안내한다.

검색어 트렌드는 같은 최대 5개를 하나의 요청으로 90일 일별 조회한다. 상대 지수 0~100이며 월간 검색량이나 광고 경쟁도, 블로그·클립 상위 노출 난이도가 아니다. 서로 다른 요청의 정규화 지수를 직접 비교하지 않는다. 응답이 빈 키워드는 ‘자료 없음’으로 표시하며 누락된 날짜를 검색수 0으로 채우지 않는다. 조회일과 기간·제공일을 표시한다. 검색 문서 수를 상대 지수로 나눈 경쟁도는 계산하지 않는다.

API 오류는 ‘미확인’으로 남기고 0으로 바꾸지 않는다. 공급사 오류 본문과 인증 헤더는 분석 결과나 로그에 저장하지 않는다. 조회 중 자료·제품 확인·프로젝트 버전이 바뀌면 결과를 반영하지 않는다. 새 조회·조사 후에는 고객 공유를 다시 확정해야 한다. 고객 보고와 보고 엑셀에는 확정할 때 저장한 값 중 확정 키워드의 데이터만 표시한다. 데이터는 추천 초안에 대한 검토 자료이며, 정량 지표만으로 추천 순위를 자동 확정하지 않는다.
