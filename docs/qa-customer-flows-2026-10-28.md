# 고객 흐름 QA · 2026-10-28

## 범위와 방법

대상: 광고주 마이페이지, 회원가입, 고객 정보 입력 링크, 제품·자료 관리, 관리자 고객 정보·자료실. 운영 사이트의 실제 응답과 서버 오류 로그를 확인한 뒤 통신 장애를 주입해 실패 경로를 재현했다. 관련 공개 페이지 12개를 390px/1440px에서 24회 확인했고, 가입 질문은 320/390/768/1440px에서 별도로 검사했다.

기존 미커밋 작업과 분리한 소스 사본에서 빌드·타입 검사·회귀 테스트를 수행했다. 쓰기 검증은 임시 DB/Storage 또는 명확히 구분한 확인용 고객만 사용하고, 승인·노출·결제 대상의 실제 고객 데이터는 변경하지 않는다. 자동 결제·참여자 선정·알림 발송·유료 AI 생성은 수행하지 않는다.

## 마이페이지 지연·실패에 대한 결론

운영의 확인용 계정에서 첫 동시 조회는 약 1.6~2.6초, 반복 조회는 약 0.4~1.4초였다. 최근 관련 경로의 치명적인 Vercel 런타임 오류는 발견하지 못했다. 따라서 사용자가 겪은 모든 실패를 특정 DB 장애로 단정하지 않는다.

대신 통신 실패를 주입하자 캠페인 조회 한 번의 실패로 제품 탭이 사라지고, 네트워크 문제인데도 로그인 안내만 보이는 현상을 재현했다. 응답이 끝나지 않는 경우에는 클라이언트 대기 제한도 없었다. 이러한 실패·복구 경로와 불필요한 순차/반복 조회를 수정했다.

## 검증 결과

- 자동 회귀 테스트: 관련 13개 파일, **55개 통과**. 주문·캠페인, 계정 상태, SMS/카카오, 제품 소유권/자료, 고객 보고서, 제품 정보 확정, 통신 복구와 조회 수를 포함한다.
- 503/502/네트워크 정지/인증 만료/잘못된 JSON을 검사했다. 저장 POST는 재시도하지 않는다.
- 캠페인 조회 실패 중 제품 진입, 제품 조회 재시도, 타임아웃 복구, 실제 저장 성공 후 목록 실패, 큰 파일의 클라이언트 차단을 브라우저에서 확인했다.
- 고객 링크 첫 접속 오류 후 재시도, 원래 링크 유지, 변경 없는 저장 생략, 작은 파일 단일 요청, 제출 후 다시 접속, 내부 코드 대신 선택지 이름 표시를 확인했다.
- 분리된 QA 서버/DB에서 관리자 계정 조회 오류 복구와 실제 자료 업로드를 확인했다.
- 공개 페이지 24회 점검: 페이지 응답 실패·가로 넘침·대체문자(�)·치명적 JavaScript 예외 없음. 자동화 환경은 Chromium이며, 실제 iOS Safari 장치 검사는 포함하지 않는다.

## 재현 가능한 브라우저 검사

앱을 Playwright CLI로 연 뒤 다음 함수를 `run-code --filename=...`으로 실행한다.

- `scripts/qa-customer-recovery.js`: 제품·캠페인 장애/복구. 제품 쓰기는 모의 처리한다.
- `scripts/qa-intake-recovery.js`: 접수 실패/임시 저장/단일 업로드/완료 요약. 접수 응답을 모의 처리한다.
- `scripts/qa-signup-accessibility.js`: 줄바꿈, 화면 폭, 전화번호, 이메일 추천과 키보드. 가입을 제출하지 않는다.
- `scripts/qa-admin-customer-recovery.js`: 격리된 QA 관리자 세션과 지정한 QA 고객에서만 실행한다.

## 운영 배포 후 확인

- 기능 커밋 `1b2deb0`의 Vercel production 배포 READY 확인 후 `https://www.onemarketing.kr`에서 검증했다.
- 검증용 광고주 제품 수정 → 새로고침 → 자료 업로드 → 다운로드가 유지됐고, 다른 고객의 다운로드는 404로 차단됐다.
- 고객 링크에서 이전 질문 답변 유지, 방문형 분기, 날짜, 작은 파일 업로드, 제출과 재접속을 확인했다. 관리자 API에서 같은 답변을 조회하고 승인한 결과가 저장됐다. 다른 링크를 연 뒤 이전 캠페인으로 저장하면 409로 차단됐다.
- 배포된 UI에서 캠페인/제품 오류 복구, 10초 조회 타임아웃, 저장 성공 뒤 목록 조회 실패, 접수 재시도, 변경 없는 임시 저장 생략, 이메일 추천과 Enter 이동, 로그인 상태 조회 실패 후 메뉴 유지의 장애 주입 검사가 통과했다. 모의 응답 검사와 실제 데이터 연동 검사를 구분해 수행했다.
- 배포 후 공개 페이지 12개를 모바일 390px·데스크톱 1440px에서 다시 검사했다. 24회 모두 HTTP 200, 가로 넘침·대체문자·pageerror 없음. 비로그인 상태에서 인증이 필요한 즐겨찾기 API의 401은 관찰됐으며 치명적인 예외와 구분했다.
- 검증 데이터 정리 완료: 임시 광고주 2개, workflow 3개, 저장 파일 3개, records 7개, 관련 events 11개. 실제 고객 데이터는 검증 수정 대상에서 제외했다.

### 응답 시간 관찰

같은 검증용 계정으로 네 API를 동시에 호출해 배포 전·후 각각 3회 측정했다. 단위 ms이며 첫 호출은 실행 환경 초기화와 네트워크 변동을 포함한다. 표본이 작아 성능 개선율을 확정할 수 없다.

| API | 전 첫 호출 | 후 첫 호출 | 전 반복 2회 | 후 반복 2회 |
|---|---:|---:|---|---|

| `/api/viewer` | 1822 | 3319 | 391, 384 | 734, 385 |
| `/api/commerce` | 2090 | 3770 | 1099, 908 | 735, 1830 |
| `/api/advertiser-products` | 2584 | 2235 | 1434, 1248 | 955, 743 |
| `/api/advertiser-auth` | 1620 | 3216 | 563, 583 | 607, 383 |

제품 반복 조회는 이 표본에서 감소했지만, 캠페인 조회 등은 변동이 있고 첫 호출 지연도 남아 있다. 이번 수정의 확인 가능한 효과는 조회 범위 축소·N+1 제거, 변경 없는 저장 생략, 작은 업로드 요청 3회→1회, 무제한 대기를 종료하고 재시도할 수 있는 동작이다. 장기 운영의 p95/p99 지연은 별도 모니터링이 필요하다.

실제 카카오 외부 동의 화면·실제 iOS Safari·실제 결제/메시지 발송은 이번 운영 검사의 대상이 아니다. 카카오 계정 연결과 소유권은 격리된 자동 테스트로 검증했다. 운영에서 작은 파일의 직접 업로드를 검증했으며, 대용량 MP4의 실제 전송은 포함하지 않는다.
