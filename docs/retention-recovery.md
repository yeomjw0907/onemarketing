# 게시물 유지 및 복구

검수 승인 시 정해진 90일 유지 종료일은 복구 요청·완료·재확인으로 연장되지 않는다. 지급 기록, 정산 및 추천료도 자동 취소하거나 차감하지 않는다.

1. 관리자: 캠페인 운영 → 검수·유지 → 프로젝트 선택 → 게시물 확인 링크에서 실제 공개 여부 확인.
2. 삭제·비공개이면 복구 요청에서 확인 결과와 요청 내용을 기록한다. 복구 기한은 캠페인의 수정 기한 설정(기본 2일)을 적용한다. 같은 진행 중 요청에 대한 반복 클릭은 알림을 중복 생성하지 않는다.
3. 참여자: 나의 작업 → 게시 작업에서 요청 내용·기한·기존 링크를 확인한다. 기존 게시물을 공개로 복구한 뒤 ‘복구 완료 알리기’를 누른다. 기한 초과라도 접수 가능하다. 새 URL이 필요한 경우 담당자에게 문의하도록 안내한다.
4. 관리자: ‘복구 완료 접수 · 재확인 필요’ 작업의 게시물을 직접 다시 확인하고 ‘공개 유지 확인’을 누른다. 복구가 안 됐다면 복구 요청을 다시 기록한다.
5. 90일 종료 후 새 복구 요청은 거부한다. 종료 전에 발생한 미해결 요청의 접수·재확인은 종료 후에도 가능하다. 각 요청·접수·확인은 감사 로그에 남는다.

## 자동 유지 확인

운영 환경 `RETENTION_MONITOR_ENABLED=true`에서 기존 Vercel 10분 Cron(`/api/jobs/run` GET) 또는 별도 worker가 실행한다. 미디어 제작 작업이 없어도 실행된다. 정상 공개 게시물은 24시간마다, 삭제 의심·판별 불가는 6시간 뒤 재확인한다. 한 번에 최대 20건, 120초까지 처리하고 다음 실행에서 남은 작업을 이어간다. 실행 lease로 중복 runner를 막고 `events`의 `retention-monitor-health`에 최근 실행·오류를 기록한다. 관리자 캠페인 운영 → 검수·유지에서 최근 실행과 수동 실행 버튼을 볼 수 있다.

- 네이버 블로그는 모바일 게시물 페이지의 원본 게시물 식별과 콘텐츠 본문을 함께 확인한다. 네이버 shorts(mediaId)·TV(/v/숫자) 주소는 일치하는 게시물 메타데이터와 영상 메타데이터가 있어야 공개로 판정한다. 클립의 JS 전용 페이지 등 증거가 불충분한 경우는 판별 불가다.
- 로그인 요구, CAPTCHA, 접근 제한, 429, 5xx, 리다이렉트, 시간 초과는 삭제로 판정하지 않는다. HTTP 200도 콘텐츠 증거 없이 공개로 판정하지 않는다.
- 자동 확인으로 정상 공개를 관찰한 이력이 있고 삭제·비공개 응답이 6시간 이상 간격으로 반복된 경우에만 복구 요청을 자동 생성한다. 복구 기한과 참여자 알림은 위의 기존 복구 흐름을 그대로 사용한다.
- 기준 공개 이력이 없는 삭제 의심, 반복된 판별 불가, 미지원 URL은 관리자 확인 대상으로만 표시한다. 단축 URL(naver.me), 인스타그램, 임의 도메인은 자동 접속하지 않고 수동 확인 대상으로 안내한다. 외부 접속은 고정된 네이버 호스트·게시물 경로에 한정하며 리다이렉트를 따라가지 않는다.
- 자동 공개 확인은 미해결 복구 요청을 임의 승인하지 않는다. 참여자의 완료 접수 후 관리자 재확인 단계를 유지한다. 90일 종료 후 새 감시는 중단하되 기존 미해결 요청은 계속 확인한다.

## 관리자 카카오톡

`RETENTION_ADMIN_ALIMTALK_ENABLED=true`, `SENS_TEMPLATE_RETENTION_ADMIN=ONERETENTIONADMINV1`. 수신번호는 `RETENTION_ADMIN_PHONE`을 사용하며 없으면 기존 본인 확인이 된 `SENS_TEST_PHONE`을 사용한다. 운영 설정은 production에만 적용하고 preview에서는 비활성화한다.

새 템플릿 이름은 ‘원케이션관리자게시유지알림’, 업무알림 → 내부 업무 알림 카테고리다. 2026-10-16 원케이션 채널에 등록해 검수 접수했으며 아직 승인·실발송을 확인하지 않았다. 본문:

```text
[원케이션] 운영 중인 캠페인의 게시물 유지 확인 알림입니다.
작업: #{name}
확인 내용: #{reason}
관리자 화면에서 게시물을 확인하고 필요한 조치를 진행해주세요.
```

웹 링크 버튼 ‘관리자 화면’의 PC·모바일 주소는 모두 `https://www.onemarketing.kr/?page=workflow`다. 각 발송 전에 승인 상태·채널·본문·버튼의 일치를 확인한다. 미승인 알림은 대기하며, 승인 후 실제 이상 알림을 처리할 때 발송한다. 기존 검수 테스트 모니터를 다시 켜거나 테스트 알림을 자동 발송하지 않는다.

관리자 알림은 참여자 `SENS_ENABLED`와 독립적이다. 참여자용 복구 안내 알림톡은 기존 템플릿 승인 및 `SENS_ENABLED` 활성화가 필요하다. 참여자 화면의 복구 요청 자체는 알림톡 승인 여부와 관계없이 표시된다. 같은 이상 회차는 중복 알림을 생성하지 않고, 해결·종료·대체된 알림은 발송 시 취소한다. 발송 결과가 불명확하면 자동 재발송하지 않는다. 관리자 화면 알림 이력에서 발송·오류를 확인할 수 있다.

검증: 격리 DB에서 본인 작업 제한, 버전 충돌, 중복 요청, 기한 종료 전후, 지급액·원본 링크·유지 종료일 보존을 확인했다. 격리 브라우저에서 참여자 접수와 관리자 재확인을 수행했고 참여자 1440/390/360px 화면을 확인했다. 실제 게시물을 삭제하거나 실제 알림을 발송하지 않았다.


추가 검증: 공개/삭제/비공개/접근 차단 분류, 6시간 간격과 공개 기준, 동시 실행 lease, 만료·오래된 결과 무시, 관리자 전용 수신번호·승인 템플릿 검사 및 해결 알림 취소를 격리 테스트했다. 네이버 블로그팀의 공개 글을 읽기 전용으로 확인해 실제 공개 판별을 검증했다. 관리자 이상 목록·수동 실행과 1440/390/360px 화면을 확인했다. 운영 DB 확인 당시 유지 대상은 0건이었다.
