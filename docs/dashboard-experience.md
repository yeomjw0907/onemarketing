# 실제 데이터 기반 운영 대시보드

관리자 `현황`의 기본 탭은 운영 현황이며 캠페인 보드를 보조 탭으로 제공한다. 기존 프로젝트 생성, 프로젝트 단계 이동, 승인 원고·이미지·영상 수량, 채널별 게시 확인, 미지급 보수, AI 비용·환율·청구 확인 기능을 유지한다. 공통 Button, Tabs, BrandOrb를 사용하고 새 레이아웃 스타일은 CSS 모듈 안에 한정한다.

## 집계 기준

- 기존 `dashboard()`의 마감·지연, 검수·수정 대기, 게시 확인 필요, 미지급 보수 집계를 유지한다. 미지급 보수에는 미완료 작업의 예정액도 들어가므로 지급 가능한 금액이라고 표시하지 않는다.
- 캠페인은 완료·취소를 제외하고 보류를 구분한다. 콘텐츠 진행 막대는 취소되지 않은 작업을 제작 준비 / 제작 중 / 검수·수정 / 게시 대기 / 게시 확인 중 하나에만 집계한다. 완료율은 게시 확인 수 / 전체 작업 수다. 작업이 없으면 비율을 표시하지 않는다. 모집은 제작과 병행 가능하므로 미배정 슬롯 수로 별도 표시한다.
- 캠페인 보드는 프로젝트의 대표 단계(자료·기획 / 제작·검수 / 게시·정산 / 보류)를 사용한다. 내부 작업이 모두 같은 단계라는 의미가 아니다. 카드에서 진행 막대와 승인본·채널별 수량을 확인할 수 있다.
- 게시 성과는 한국 시간의 실제 `verifiedAt` 기준으로 이번 주·이번 달을 집계한다. 날짜 없는 완료를 `updatedAt`으로 대체하지 않는다. 취소 프로젝트·취소 작업·연결되지 않은 작업은 제외하고 완료 프로젝트의 실제 게시 이력은 포함한다.
- 주간 목표 링은 이번 주가 `scheduledUntil`인 작업 집단 중 현재 게시 확인이 된 비율이다. 해당 기간에 실제 확인한 총건수와는 집계 대상이 다르다. 저장된 일정이 없으면 목표를 만들지 않는다. 보류는 예정 집계에서 제외하고 이미 완료한 실적은 남긴다. 미등록 일정과 누락된 확인일을 따로 알린다.
- 그래프의 실적과 마감 예정·미완료 물량을 나란히 표시하고 무늬로 구분한다. 화면 판독기와 정확한 수량 확인을 위해 일자별 수량 표도 제공한다.

## 업무 연결과 갱신

먼저 처리할 일은 기존 `projectActions()`를 사용한다. 완료 캠페인의 게시 유지 이상도 놓치지 않고 상단에 표시한다. 복구·부분 정산은 기존 캠페인 운영의 검수 화면으로, 제안·전달은 배정 화면으로, 일반 검수는 해당 프로젝트 탭으로 연결한다. 카드는 기존 대시보드의 다음 할 일과 이동 목적지를 유지한다.

기존 워크스페이스의 12초 데이터 갱신을 사용한다. 실제 `running` AI 작업만 Orb를 표시하며 큐 대기·상태 확인 필요에는 정적인 표시를 사용한다. 서버 작업 상태 변경 후 자동 갱신으로 Orb가 제거되는 것을 확인했다. 생성·게시·정산을 대시보드에서 자동 승인하지 않는다.

## 검증

- TypeScript 및 프로덕션 빌드 통과.
- 자동 테스트 197개 통과. 새 테스트는 한국 날짜 경계, 월·연도 경계, 취소·보류 제외, 확인일 누락, 목표 집단과 실적 구분, 완료 캠페인 복구, 실제 AI 상태를 검증한다. DB 연결 한도 초과로 실패한 최초 전체 실행은 동시 실행 2개로 제한해 전체 재검증했다.
- 별도 QA 스키마에 실제 견적 확정으로 만든 프로젝트를 사용해 PC 1440/1024px, 태블릿 768px, 모바일 390/360px 가로 넘침이 없음을 확인했다.
- 기본 탭, 필터, 기간 전환, 수량 표, 보드 검색, 검색 조건 격리, 복구 화면 이동, 프로젝트 이동, 프로젝트 생성 진입, 기존 비용 화면, 실데이터 자동 갱신을 확인했다.
- 실제 메시지·유료 AI·송금은 실행하지 않았다. QA용 DB 스키마와 임시 로그인 정보를 검증 후 삭제했다.
