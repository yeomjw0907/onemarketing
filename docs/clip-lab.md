# 클립 퀄리티 고도화 대작전!연구소

2026년 11월 3일에 추가한 로컬 연구소 MVP다. 공개 YouTube 영상의 앞 30초를 Gemini에 영상 입력으로 전달하고 장면별 관찰, 연속성, 재현 방법, 실험 가설과 사용량을 저장한다. vidIQ와 다른 유료 MCP는 호출하지 않는다.

아래는 최초 30개 시험의 동작이다. 추가 1,000개 분석, 관찰 카탈로그, 기존 브리핑의 시작·끝 상태 검수와 HyperFrames 편집기는 [확장 구현 문서](clip-lab-production.md)를 따른다.

## 실행

Node.js 22 이상에서 실행한다. 별도 패키지 설치 없이 Node 내장 모듈로 동작한다.

```powershell
# 기존 결과를 열어보는 경우. 키가 없어도 열람·검색·검토 저장 가능.
$env:CLIP_LAB_DATA_DIR = '결과를 저장한 폴더의 절대 경로'
npm run clip-lab
```

출력된 `http://127.0.0.1:4317`에 접속한다. 서버는 루프백 주소에만 바인딩하며 정확한 Host와 Origin을 검사한다. 같은 컴퓨터의 사용자를 신뢰하는 내부 도구다. 인터넷 공개나 고객용 배포에 쓰지 않는다.

새 분석은 서버 프로세스의 GEMINI_API_KEY 또는 GOOGLE_API_KEY를 사용한다. GEMINI_VIDEO_ANALYSIS_MODEL을 지정할 수 있다. 기본값은 이번 시험에서 접근 가능한 것으로 확인한 gemini-3.1-flash-lite다. 키를 브라우저나 URL로 전달하지 않는다. 필요한 경우 기존 비공개 env 파일 경로를 GEMINI_ENV_FILE에 지정할 수 있다. 키와 데이터 폴더는 git에 추가하지 않는다.

```powershell
# 비공개 환경변수를 이미 설정한 상태에서 배치 실행
npm run clip-lab:batch -- scripts/clip-lab/manifest.json
# 검증과 오프라인 결과 보고서 생성
npm run clip-lab:test
node scripts/clip-lab/export.mjs '데이터 폴더' '보고서.html'
```

브라우저의 영상 등록 기능은 한 줄에 URL 하나를 받는다. 전체 실험의 최대 영상 수는 30개다. 전체 분석 버튼은 아직 기록이 없는 URL만 호출하며, 중지 버튼은 현재 요청 다음부터 실행을 멈춘다. 현재 요청의 과금을 취소하지는 않는다.

HTTP 503으로 거절된 요청은 관리자가 재시도 버튼을 눌렀을 때 한 번만 다시 보낸다. 첫 요청은 attempts 폴더와 priorAttempts에 남긴다. retry-locks의 독점 생성으로 동시 재시도를 막는다. 403, 전송 불확실, 잘린 응답은 자동 재시도 대상이 아니다. 같은 데이터 폴더에서는 배치와 서버의 분석 실행을 동시에 시작하지 않는다.

## 현재 구현 범위

- 영상 URL 정규화, 중복 제거와 30개 한도.
- YouTube oEmbed로 원본 제목과 채널명을 확인하고 검색 당시 제목과 분리. 주제 분류는 검토 전 임시 분류로 표시.
- 2 FPS, 최대 30초 영상 입력과 한국어 구조화 응답 요청.
- 화면 접근 여부, 장면 범위·중첩, 가설의 근거 장면 참조 검증.
- 장면의 목적·화면·행동·카메라·소리·자막·전환·연속성·재현 방법 기록.
- 독립 JSON 파일과 원자적 교체를 통한 로컬 보관. 동시 생성은 exclusive create로 중복 전송 방지.
- 모델과 입력 설정·프롬프트 버전을 포함한 식별자. 기존 완료·실패·불확실 기록은 자동 재호출하지 않음.
- 실패 응답과 전송 불확실 상태 분리. 출력 잘림과 스키마 오류는 성공으로 취급하지 않음.
- 사용량 원본과 공식 표준 가격에 따른 추정액. 오디오·thinking 토큰을 고려하고 실제 청구액은 별도 미확인.
- 검색, 분야·상태 필터, YouTube 원본 링크·임베드, 장면 시점 이동, 검토 메모와 버전 충돌 검사, 검토 이력, JSON 내보내기.
- 서버가 없어도 열어볼 수 있는 읽기 전용 HTML 보고서 생성.

원본 응답 전문은 저장하지 않고 검증된 결과·사용량·기계적 오류 코드만 저장한다. 키·헤더와 임의의 공급사 오류 메시지는 기록하지 않는다.

## 상태와 검토

작업 상태는 prepared, sending, validating, succeeded, rejected, uncertain, invalid_result, failed다. 중간 상태에서 프로세스가 종료되면 기존 기록을 유지하며 다음 실행에서 자동 재전송하지 않는다. 운영자가 공급사 상태와 비용을 확인해야 한다. 중단된 중간 상태의 자동 복구는 구현하지 않았다.

같은 폴더를 사용하는 여러 프로세스의 분석 요청 중복은 파일 독점 생성으로 막지만, 검토 버전 충돌 처리는 단일 서버 프로세스 안에서만 직렬화한다. 다중 서버나 다중 사용자 운영을 위한 DB 트랜잭션을 대신하지 않는다.

검토 상태는 unreviewed, source-checked, rejected다. source-checked는 원본과의 대조 상태이며 연출 효과를 입증했다는 뜻이 아니다. 가설은 생성 실험 결과가 연결되기 전까지 제작 규칙으로 자동 채택하지 않는다. 일부 프레임만 확인했다면 unreviewed를 유지하고 메모에 확인한 범위를 남긴다.

## 표본과 해석

첫 manifest는 웹 검색에서 찾은 후보 30개이며, 6개 분야에 5개씩 배분했다. 제목·주제·출처를 수동으로 기록한 탐색 표본이다. 전체가 고성과 사례이거나 YouTube에서 Shorts로 확인된 표본이라고 보장하지 않는다. 순위·성공 원인·전환 성과를 검증하는 실험이 아니다.

앞 30초만 분석하므로 영상 전체의 결말이나 효과를 평가하지 않는다. YouTube URL 입력 접근성, 언어 준수, 구조화 응답과 비용을 검증하는 시험이다. 실제 영상 길이와 프레임의 정확한 컷 시점, 음성 정확도는 별도 대조가 필요하다. 구조 검증 통과와 내용 정확도를 구분한다.

## 다음 서비스 통합 경계

이번 구현은 독립 로컬 연구소이며 기존 Next.js 고객 UI, 운영 DB, 기존 작업 큐, 영상 생성 공급사를 변경하지 않는다. 대량 분석부터 바로 운영 프로젝트에 연결하지 않기 위한 첫 실험 범위다.

운영 통합 때에는 로컬 파일 저장을 DB·비공개 객체 저장 어댑터로 교체하고 관리자 인증, 프로젝트 권한, 계정별 예산 예약, 작업 lease, 보관·삭제 정책을 연결해야 한다. 현재 in-process 실행기는 재배포를 넘기는 내구성 큐가 아니며 서버리스 저장에 적합하지 않다. 장면 생성·조립·자동 검수와 비교 실험 실행은 후속 구현이다.

## 가격 근거

[Gemini 공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)의 2026년 11월 3일 표준 단가를 사용했다. gemini-3.1-flash-lite 입력은 텍스트·이미지·영상 100만 토큰당 0.25달러, 오디오 0.50달러, 출력은 thinking을 포함해 1.50달러다. 캐시 입력 등 계산을 지원하지 않는 조합은 미확인으로 남긴다. 무료 한도나 프로모션, 실패 요청의 청구, 세금은 실제 청구 조회로 확인해야 한다.
