## 이번 배포 범위

기존 운영 main(0430d1a)에서 분리한 작업 폴더에서 수정했다. 영상 학습 세션의 미완료 변경은 포함하지 않았다. 네이버 소셜 로그인은 계속 비활성 상태이며 검색어드바이저의 색인 확인과 별개다.

복귀 주소는 역할별 허용 목록으로 검증한다. 외부 URL, 임의 쿼리, 인증 토큰은 전달하지 않으며 일회성 복귀 쿠키는 인증 콜백에서 삭제한다. 기존 캠페인·추천 코드 흐름과 인증 권한 범위는 유지한다.

## 검증

- 전체 테스트: `npx tsx --test --test-concurrency=2 tests/*.test.ts` — 332개 통과, 실패/생략 0.
- `npm run typecheck`, `npm run build`, `git diff --check` 통과.
- 기본 병렬 테스트 실행은 공유 DB의 15개 세션 제한에 걸려 일부 실패했다. 병렬도를 2로 제한한 전체 재실행으로 검증했다.
- 운영 빌드 + 격리 DB 스키마에서 실제 HTTP OAuth 시작/상태/쿠키/콜백을 검사했다. 카카오·구글 각각 광고주 정상 복귀/외부 URL 차단, 참여자 정산 복귀/타 역할 주소 차단 8개 시나리오 통과. 제공자 토큰·프로필 응답만 격리 서버에서 모의 처리했으며 실제 제공자의 로그인 화면을 재검증한 결과와는 구분한다. 운영 Secure 쿠키 설정은 유지했다.
- 브라우저에서 이메일 로그인 후 주문 탭 복귀, 신규 광고주 첫 캠페인 안내, 참여자 기본 지원 탭, 정산 탭 새로고침 유지를 확인했다.
- 참여 수량 저장 직후 조회를 강제로 두 번 실패시켜 자동 GET 재시도까지 소진시켰다. 저장 완료/조회 실패 안내와 재조회 버튼을 확인하고, 재조회 후 실제 저장 수량 3과 선택 탭이 복구됨을 확인했다. 운영 사용자 데이터나 실제 주문·메시지 전송은 사용하지 않았다.

## 검색 노출 상태와 남은 과제

Google의 서비스 소개(`/about`)·상품 소개(`/marketing`)는 이전 URL 검사에서 색인을 확인했다. 네이버는 소유확인·사이트맵 제출·수집 요청을 마쳤지만 이번 조회에서는 두 URL 모두 검사 결과/수집 데이터가 없어 실제 색인을 확인하지 못했다. 실제 페이지는 HTTP 200이며 색인 허용 상태다. robots 수집 갱신도 요청되어 외부 처리 대기 중이다. 반복 배포로 해결되는 코드 오류로 판단하지 않는다. [네이버 수집 요청 안내](https://searchadvisor.naver.com/guide/request-crawl)

다음 성장 우선순위는 실제 운영 데이터를 바탕으로 진행한다.

1. 신규 가입→첫 지원/첫 주문→완료·정산의 단계별 이탈률을 측정해 가장 큰 병목부터 개선한다.
2. 상품의 제공 범위·일정·검수/수정 기준과 실제 운영 가능한 캠페인 공급을 충실히 확보한다. 빈 상품/캠페인을 가짜 사례로 채우지 않는다.
3. 운영이 축적되면 동의받은 실적·검증된 후기와 재주문 흐름을 강화한다.
4. 정산 실패·반려·재제출·환불 등 예외 처리의 운영 시간을 측정하고 담당자/사용자 안내를 개선한다.
