# 서비스 전체 흐름 QA (2026-11-08)

진행 중. 기준 커밋: 1a6df5f. 별도 작업 폴더와 codex/service-lifecycle-qa 브랜치에서 점검한다. 원본 작업 폴더의 미커밋 파일은 포함하지 않는다. 영상 세션의 분리 브랜치 codex/clip-learning-20261108 (2e5adac)를 병합 대상으로 확인했다.

## 검증 기준

관리자: 로그인 → 모집/주문 관리 → 입금 확인 → 선정/배정 → 제작/검수 → 지급/환불 → 계정 요청 처리.
광고주: 가입/로그인 → 제품/자료 → 주문/입금 → 캠페인/지원자 → 검수 → 취소/환불 → 계정 관리.
참여자: 가입/승인 → 인증 → 지원/수락 → 자료/게시/수정 → 정산 → 계정 관리.
운영 데이터 쓰기는 하지 않는다. 결제·메시지·유료 AI는 격리 환경에서 모의 처리한다.

### ISSUE-002 · 높음 · 작업 조회 장애를 로그인 화면으로 오인하고 재시도할 수 없음

- 503 응답을 주입하면 로그인 화면이 나타나고 재시도 버튼이 없다. 기존 서버 GET도 DB/조회 실패를 모두 401로 반환했다.
- 증거: C:/dev/one_marketing/output/playwright/service-qa-002-portal-outage-before.png
- 수정: DB 오류 503, 인증 실패 401, 조회 실패 500 분리. 공통 요청 시간 제한·오류 처리 적용. 재시도 제공. 접속 링크 제거 시 다른 query 값 유지 (8517163).
- 검증: 503에서 로그인 버튼 없이 재시도 표시. 모의 응답을 해제한 뒤 다시 불러오기로 격리 DB의 실제 회원 작업으로 복구했다.
- 수정 후 증거: C:/dev/one_marketing/output/playwright/service-qa-002-portal-outage-after.png

### ISSUE-003 · 높음 · 탈퇴·개인정보·정산 문의 접수와 담당자 처리 경로 없음

- 인증된 참여자 포털에도 탈퇴·개인정보 요청 접수 기능이 없다. 가입 안내에는 탈퇴 시 삭제 문구가 존재한다.
- 증거: C:/dev/one_marketing/output/playwright/service-qa-003-account-before.png
- 수정: 본인 역할별 접수·목록·철회, 관리자 확인·답변과 감사 기록. 중복 접수와 타인 접근 차단 (7c5fb1a, 554e5a4).
- 검증: 브라우저에서 접수 → 새로고침 후 유지 → 관리자 확인 시작 → 답변 → 본인에게 답변 표시. 종료 후 철회 불가. 미인증 세 역할은 각각 401, 교차 출처 요청은 거절. 자동 테스트에서 다른 회원·역할 격리, 동시 중복, 버전 충돌을 확인했다.
- 수정 후 증거: C:/dev/one_marketing/output/playwright/service-qa-003-account-after.png
- 범위: 접수와 답변이 실제 탈퇴/삭제를 실행하지 않음을 명시한다. 실제 개인정보 파기·거래 기록 보존·외부 공급자 계정 해지는 별도 업무로 남는다.

### ISSUE-004 · 치명적 · 대행 환불 요청에서 확정 수행액이 소실됨

- 재현: 대행형 캠페인 결제액 170,000원 → 관리자 수행액 reward 20,000 / operation 5,000 / managed 20,000 저장 → 환불 요청.
- 결과: 완료 인원이 0명이라는 이유로 reward/operation을 0으로 덮어쓰고 총 수행액이 45,000원에서 20,000원으로 감소한다. 환불 한도가 25,000원 과다해질 수 있다.
- 격리 DB와 브라우저 UI에서 실제 재현했다. 증거: C:/dev/one_marketing/output/playwright/service-qa-004-refund-before.png

- 검증: 같은 캠페인 환불 요청 반려 → 수행액 45,000원 재확정 → 새 환불 요청에서 수행액 유지. 환불 150,000원 승인 요청은 400으로 거절. 자동 테스트에서는 정확한 상한 125,000원만 승인되고 수행액 유지.

## 검증 결과 (영상 병합 전)

- 전체 TypeScript 테스트 295/295 통과. 첫 실행 7건의 DB session pool 한도 실패를 그대로 기록한 뒤 DATABASE_POOL_MAX=2 / --test-concurrency=2로 전체 재실행했다. 테스트·CI 설정 파일을 바꾸거나 실패 테스트를 삭제하지 않았다.
- 신규 회귀 검사: 계정 요청 2개, 대행 환불 1개, 지급 대기열 1개.
- 320/390/768/1440px × 6페이지(account, admin/account-requests, participants/portal, signup, login, advertisers) 24회: HTTP 200, 가로 넘침 없음, main 1개, pageerror 0건. 인증된 QA 세션으로 확인했다.
- 광고주 가입 질문부터 가입 완료까지 실제 DB 저장 확인 (이메일 중복·소유권 등은 기존 자동 테스트 포함). 가입 후 HTTP 주문/결제 테스트는 실제 생성된 광고주 세션을 사용했다.
- 결제·환불·송금은 격리 DB의 기록만 생성했다. 은행 송금, 실제 카카오 동의, SMS 발송, 유료 AI 호출은 하지 않았다.
- 타입 검사 통과. 기준 production build 성공. 최종 빌드와 병합 후 검증은 별도 기록한다.
- 5건 수정 후 스킬 자체 점검: 되돌림 0, 세 파일 초과 기능 수정 1건, 위험도 휴리스틱 5%. 수정과 직접 관련 없는 파일 변경 없음.

## 추가 개선 아이디어와 남은 운영 범위

- 탈퇴·개인정보: 현재 본인 요청/철회와 담당자 답변까지 지원한다. 실제 데이터 삭제와 보존 이력 분리, 외부 카카오/MCP 해지·파일 파기를 자동 실행하는 기능은 포함하지 않는다. 답변 등록을 탈퇴 완료로 표시하지 않는다.
- 로그인 복구: 이메일 계정의 비밀번호 재설정 메일 발급 경로가 없다. 인증된 요청 게시판이 로그인 불가 사용자의 복구를 대체하지 못한다. 검증된 메일 발송 채널과 일회용 복구 토큰을 통한 별도 기능이 필요하다.
- 계정 요청: 관리자에게 본인/거래 정보로 바로 이동하는 연결, 미지급·환불 현황을 함께 제시하는 처리 화면, 대기 시간과 담당자 배정, 페이지 단위 조회를 후속 개선으로 권장한다. 현재 최근 관리자 200건/회원 100건이다.
- 정산: 지급 대기열은 추가했다. 실제 은행 증빙/수취인 대사, 지급 기한과 이의 제기 SLA, 세무 서류는 운영 정책을 구체화한 후 연동할 수 있다.
- 가입: 사업자·연락처·콘텐츠 소유 확인이 외부 본인확인 자체를 보장하지 않는다. 실제 카카오·휴대폰 인증과 기기 검증은 운영 계정으로 별도 인수해야 한다.
- 품질 점수: 확인한 결함은 재검증하지만, 실제 외부 공급자·송금·개인정보 파기까지 검증하지 않은 서비스 전체를 100점이라고 판정하지 않는다.

## 초기 검증·환경 기록

- 핵심 8개 테스트 파일 50개 통과. 결제·환불·중복 요청·동시 선정·정산·인증을 포함한다.
- 첫 실행은 원본 node_modules를 공유했으며 최종 검증은 별도 설치로 다시 수행한다.
- 포털 인증 테스트에서 Storage 정리 경고 1건이 있어 최종 검증에서 확인한다.
- 기준 빌드는 외부 node_modules 연결을 Turbopack이 허용하지 않아 실패했다. 별도 의존성 설치 중 네트워크 ECONNRESET이 발생해 재시도 중이다.
- 병합·푸시·배포는 아직 수행하지 않았다.
