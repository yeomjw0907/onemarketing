# 기획 검토 기록 v0.1

- 날짜: 2026-10-14
- 검토 방식: 확정된 A 범위를 유지하고, 미결정 운영 규칙은 추천 기본값으로 명시. 사용자 요청에 따라 별도 승인 질문 없이 초안을 구체화.
- 대상: product-spec-v0.1.md
- 상태: DONE_WITH_CONCERNS — 기획 검토·명세 초안 완료. 코드·API 실행·운영 성과 검증은 수행하지 않음.

## 1. 아키텍처

고정된 운영 워크플로우가 현재 요구에 가장 직접적이다. 범용 노드 편집기는 초기 가치에 비해 복잡하다. GPT 판단과 시스템의 상태·금액·권한을 분리하고, 영속 큐와 별도 worker로 실행한다. 생성 도중 브라우저가 닫혀도 작업은 유지되어야 한다. 현재 신규 저장소이므로 재사용 가능한 운영 코드 없음. wiki를 초기 통합하지 않는 결정을 유지한다.

## 2. 오류와 복구

인증 실패, 한도 초과, 일시 오류, 응답 유실, 파일 수집 실패, ZIP 누락, 비용 미확정을 개별 오류로 정의했다. 성공한 생성분 보존과 요청 상태 확인을 통해 무조건 재생성하는 비용 위험을 줄인다. 세부 예외 클래스·처리 함수는 API adapter 구현 시 확정한다.

## 3. 보안과 자료 경계

운영자 인증, 서버 전용 API 키, 비공개 파일, 고객별 검색 범위를 초기 범위에 포함했다. 외부 자료를 실행 지시로 취급하지 않는다. URL 무차별 서버 조회와 파일 수식 실행을 제외한다. 정산용 민감 식별정보 수집은 초기 불필요하므로 제외했다. 배포 환경의 백업·권한 설정은 구현 후 검증 필요.

## 4. 데이터 흐름과 상호작용

자료 없음·빈 파일·손상 파일·외부 서비스 오류 경로를 명시했다. 더블클릭·응답 유실·여러 탭 충돌·승인 후 수정·부분 납품을 추가했다. '파일 전달 = 게시 완료', '링크 등록 = 게시 확인'으로 처리하지 않도록 분리했다.

## 5. 코드 품질과 복잡도

구현 전이라 코드 결함 평가는 불가하다. 가격 계산을 단일 모듈로 두고, 공급사 응답·비용을 adapter로 정규화할 것을 권장했다. 자유형 워크플로우·범용 플러그인·멀티 고객 포털을 초기에 만들지 않는다. 모델 선택은 교체 가능 설정으로 관리한다.

## 6. 검증 계획

금액·단가 스냅샷·상태 전환·권한·중복 실행의 자동 검증, 자료 등록부터 정산까지의 통합 검증, 실제 제품 기반 제작 품질 검수를 분리했다. 실제 공급사 비용과 영상 편집 소요시간은 아직 미측정이다. 주요 경로는 명세의 Mermaid 흐름과 16절 인수 기준에 대응한다.

## 7. 관측과 운영

다음 행동·지연·실패·예산 위험을 대시보드 중심으로 둔다. 요청 ID·마지막 갱신·실행시간·비용 차이를 기록하고, 인증 실패·정체·저장 실패 복구 절차를 배포 전 준비한다. 불필요한 외부 알림 전송은 초기 범위에 추가하지 않았다.

## 8. 데이터베이스와 상태

계약·월별 슬롯·프로젝트·게시 작업·생성 실행·결과물 버전·승인·정산을 분리했다. 단가 변경은 과거 계약을 변경하지 않는다. 운영 완료와 정산 마감도 분리했다. 금액 고정 소수, 중복 키 유일성, 삭제 대신 조정 이력이 필요하다. 스키마·마이그레이션 검토는 구현 단계에 수행한다.

## 9. API 계약

초기 사용자는 운영자뿐이다. 원고/이미지/영상 생성 요청은 내부 작업 ID와 입력 버전을 갖고 비동기로 실행한다. 공급사별 인증·사용량·요청 상태를 정규화한다. 웹훅 사용 시 서명 검증·중복 수신 처리는 구현 계약에 포함한다. SNS 게시 endpoint는 공식 채널 지원 검증 후 후속 단계에서 설계한다.

## 10. 성능과 확장

병목은 LLM 텍스트보다 대용량 이미지·영상 생성/편집/ZIP일 가능성이 높다. worker 동시 실행 제한, 공급사 속도 제한, 썸네일, 목록 페이지네이션, 파일 스트리밍을 구현 시 검토한다. 10배 작업량에서 운영자 검수 대기량과 API 예산이 먼저 드러나도록 지표를 둔다. 100배 규모를 미리 전제로 복잡한 인프라를 구축하지 않는다.

## 11. 디자인과 사용성

TDS Mobile은 모바일 대상이므로 패키지 도입과 시각적 참조를 구분했다. 사용자 결정대로 간결한 토스 느낌을 자체 PC 디자인 토큰·표·비교 패널에 적용한다. 빈 화면·필터 결과 없음·일부 실패·저장 상태·키보드 접근을 명세했다. 실제 화면을 만들지 않았으므로 시각 검수는 후속 수행한다.

## 핵심 수정 권고와 반영

1. 고정 11계정 모델 → 유동 게시 작업과 담당자 배정.
2. 전체 재생성 → 승인 버전 보존과 부분 재생성.
3. 단순 실제 지출 계산 → 발생 원가·잔여 예상비·최종 마진 분리.
4. 한 번의 완료 상태 → 운영 완료/정산 마감 분리.
5. 장기계약 즉시 전체 제작 → 월별 제공 슬롯 활성화.
6. 모바일 TDS 그대로 도입 → 토스 느낌의 자체 PC 대시보드.

## 다음 검증 과제

대표 제품 1개와 실제 엑셀을 기준으로 필드 매핑, 원고 1건·이미지 묶음·숏폼 샘플의 품질과 비용을 확인한다. 아직 샘플/API 실행은 하지 않았다. VAT 조건·게시자 단가·월별 이월 조건은 운영 설정 또는 계약 템플릿에서 확정해야 한다.
