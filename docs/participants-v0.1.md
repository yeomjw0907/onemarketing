# 참여자 관리 추가 명세·구현

작성일: 2026-10-14. 대상은 운영자이며 게시자 로그인 포털과 별개다.

## 기능

- 참여자 이름·닉네임·연락처·관심 분야·내부 메모·활동 상태 등록/수정.
- 한 사람의 블로그·클립·SNS 다중 계정과 계정 별칭·링크 등록.
- 블로그/클립 기본 지급 단가 관리. 작업에서 명시적으로 적용하며 과거 보수를 자동 변경하지 않음.
- 프로젝트 작업의 참여자·계정 선택. 배정 당시 이름·계정 링크 스냅샷 저장.
- 개인별 프로필, 자동 참여 이력, 정산 이력. 고객·제품·프로젝트·게시 링크·지급일 확인.
- 시스템 외 과거 협업 수동 입력/수정. 참여일, 고객·제품, 링크, 금액, 지급 여부·지급일, 메모.
- 참여자 상세에서 프로젝트로 이동하거나 작업별 지급 완료/취소 기록.

## 데이터와 금액

현재 저장 계층에 participants / participant_history 레코드 종류를 추가했다. 기존 tasks는 participantId, participantAccountId, participantSnapshot으로 연결한다. 기존 담당자명만 있는 작업은 유지하며 자동으로 특정 참여자에게 추정 연결하지 않는다.

과거 수동 이력은 프로젝트 비용에 중복 반영하지 않는다. 개인 정산 합계에는 현재 작업과 수동 이력을 함께 표시한다. 금액 미정은 0원 확정으로 취급하지 않고 별도 안내한다. 취소 작업은 보수 의무가 남거나 이미 지급했을 때만 합계에 포함한다.

## 보호 규칙

- 같은 계정의 중복 등록과 javascript 등 비웹 URL 차단.
- 새 배정은 활동 중인 참여자와 해당 게시 채널의 등록 계정으로 제한.
- 진행 중인 작업에서 사용하는 계정 삭제 차단.
- 기본 단가 수정이 기존 작업 지급액에 소급되지 않음.
- 지급 완료 작업의 참여자·계정·금액 변경 차단. 정산 마감 프로젝트는 기존 마감 규칙 유지.
- 과거 협업 이력의 참여자 변경 차단, 정산 수정 이력 기록.
- 수정 시 레코드 종류·버전을 확인해 잘못된 레코드 수정과 동시 수정 덮어쓰기 방지.

## 검증

타입 검사와 기존 회귀 테스트에 참여자 테스트 3개를 추가해 총 10개를 검증한다. 등록·다중 계정·중복/위험 URL, 배정·단가 소급 방지·지급 후 변경, 보류 상태·과거 정산·버전 충돌을 포함한다. 브라우저와 HTTP 인수 검증 결과는 최종 보고에 기록한다.

## Supabase 인계

Supabase 프로젝트 및 MCP 연결은 아직 준비 전이다. 검색에서 Supabase 연동을 찾았으며 설치·연결이 필요하다. 연결 후 프로젝트 식별자를 확인하고 이 앱 전용 DB/Storage/접근 제어를 준비한다. 실제 비밀 키는 채팅·Git에 저장하지 않는다.

전환 시 참여자, 계정, 작업 연결, 과거 협업 이력을 함께 이전하고 레코드 ID를 보존한다. 지급 완료 금액과 링크·승인·정산 이력이 누락되지 않는지 대조한다. 다른 세션의 AI 공급사 전환 파일은 이 작업에서 수정하지 않는다.

## 本次 검증 결과

- TypeScript, 전체 테스트 10개, production build 및 포맷 검사 통과.
- HTTP 인수 검증에서 참여자 등록 → 계정 배정 → 게시 확인 → 지급 완료 → 과거 협업 이력 등록 → 정산 마감 확인.
- 브라우저에서 참여자 목록/상세, 참여 이력 2건, 지급 완료 15,000원 집계를 확인.
- 인수검증 DB는 실제 운영 DB와 분리했으며 운영 데이터에 예시 참여자를 추가하지 않음.
