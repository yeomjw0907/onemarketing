## 화면과 데이터

- 공통: 역할에 따른 계정 메뉴, 로그인/가입 분기, 모바일 메뉴, 본문 바로가기.
- 메인: 실제 모집·선정·활동 캠페인 수, 업종 선택, 검색, 채널·진행 방식·지역·혜택·상태·정렬, 캠페인 카드, 광고주 등록 안내.
- 목록: 좌측 업종·상태 메뉴, 모바일 선택 메뉴, 검색 결과와 페이지 이동. 관심 캠페인은 이 브라우저에 저장된 항목만 보여준다(기기 간 동기화는 제공하지 않음).
- 상세: 제목·브랜드·일정·모집·리워드는 공개. 원고/상세 가이드는 서버에서 로그인 여부를 확인한 후에만 반환한다. 비회원 응답에 원문을 넣어 CSS로 가리는 방식을 사용하지 않는다.
- 로그인 후: 기존 캠페인으로 돌아오기, 승인·소유 확인된 계정으로 지원, 이미 지원한 상태 표시. 다른 체험단의 지원 정보는 반환하지 않는다.
- 광고주/관리자: 기존 주문·입금·선정·검수·환불 흐름 유지. 공개 분류와 대표 이미지를 수정할 수 있다. 지원자가 있으면 방식·지역 변경을 차단한다.
- 체험단: 기존 가입/계정 검증/게시·정산 기능을 유지하고 공통 헤더와 가이드를 연결했다.
- 문서: 이용 가이드와 AI·MCP 문서를 별도 정보 구조로 정리한다.

## 운영 판단과 경계

1. 결제 미확인 캠페인은 공개하지 않는다. 실제 캠페인이 없으면 빈 상태를 표시하며 시안용 업체/이미지/신청 인원을 운영 DB에 넣지 않는다.
2. 모집 마감 후에는 신규 신청을 막고 선정 상태로 표시한다. 선정과 체험단 수락은 구분한다. 마감 임박 표시는 한국 날짜 기준이다.
3. 게시 작업과 연결된 제작 프로젝트를 별도 공개 캠페인으로 중복 노출하지 않는다. 기존 `?campaign=` 주소도 상세 URL로 연결한다.
4. 공개 데이터에서 상세 가이드를 제거하고 개인 연락처·지원자 목록을 공개하지 않는다. 관리자/광고주 권한과 기존 원가·추천료·결제/환불 계산은 그대로 검증한다.
5. 대표 이미지는 사용 권한이 있는 HTTPS 주소를 입력한다. 미등록/로딩 실패 시 브랜드 이름을 표시한다. 외부 이미지를 서버가 다운로드하거나 임의로 생성하지 않는다.
6. 카테고리/진행 방식/지역은 선택 입력 데이터로 확장해 기존 주문 재시도의 가격/요청 해시를 바꾸지 않는다. 배송/방문은 분류와 가이드로 안내하며 자동 배송·예약 기능을 약속하지 않는다.
7. MCP는 견적·주문 접수까지만 제공한다. 입금 확인 전 공개나 자동 결제·송금으로 오해할 문구를 쓰지 않는다. 연결 무료와 캠페인 유료는 구분한다.
8. 리워드 지급일, 유지 의무, 환불은 실제 약정·정책을 안내한다. 디자인 변경으로 단가나 환불 기준을 새로 만들지 않는다.

## 검증

타입 검사, 프로덕션 빌드, 전체 자동 테스트와 격리 DB의 HTTP 역할별 수용 검증을 수행한다. 별도 브라우저에서 데스크톱/모바일, 공개 목록·잠금 상세·인증 상세·문서·마이페이지를 확인한다. 테스트 캠페인은 격리 스키마에서만 생성한다.

검증 결과: 전체 테스트 **272개 통과**, 프로덕션 빌드 및 타입 검사 통과. HTTP 검증에서 주문·입금·지원·선정·검수·환불·MCP/OAuth와 15개 공통/역할별 페이지 및 캠페인 상세 응답을 확인했다. 브라우저에서 체험단 계정으로 실제 지원 후 상태 전환을 확인했고, 390px 모바일의 메인·잠금 상세·체험단·광고주 화면에 가로 넘침이 없었다. 외부 서비스의 실제 송금·문자 발송은 수행하지 않았다.
