# 카카오 광고주 온보딩·관리자 저장 검증

검증일: 2026-10-28 (한국 시간). 기능 배포 `139f13f`, 운영 Vercel READY 확인 후 `https://www.onemarketing.kr`에서 검증했다.

## 확인한 범위와 인증 경계

카카오 개인 계정의 실제 동의 창에 로그인하지 않았다. 외부 토큰·프로필 응답을 대체한 격리 HTTP 서버에서 실제 시작/콜백 라우트를 실행하여 신규 광고주의 `/login?role=advertiser&signup=1` 이동, pending 쿠키 인식, 콜백 state 재사용 차단을 검증했다. 연결 계정의 재로그인·기존 계정 연결·연결 해제는 격리 자동 테스트로 확인했다.

운영 사이트에서는 검증용 카카오 신원의 인증 대기 레코드를 생성했다. 그 상태에서 브라우저로 **실제 운영 social-register API**에 온보딩을 제출했다. 이 구간의 API·DB는 모의 처리하지 않았다. 인증 대기 레코드는 가입 후 소비됐고, 로그인 세션·카카오 연결·고객 연결이 생성됐다. 실제 카카오 외부 로그인까지 완주했다는 의미는 아니다.

## 발견하고 수정한 누락

가입한 담당자·휴대전화가 광고주 계정과 고객의 합쳐진 연락처에는 저장됐지만, 고객 마스터의 개별 필드에는 없었다. 정보입력 링크는 이 개별 필드로 기본값을 만들고 있어 담당자·전화번호가 비어 있었다.

- 고객 스키마에 `contactName`, `phone`을 추가하고 이메일·카카오 가입 모두 저장한다.
- 관리자 고객 상세와 수정 화면에 담당자·휴대전화를 표시한다.
- 이전 고객에 개별 필드가 없으면 연결 계정이 정확히 하나인 경우 기본값을 가져온다. 명시된 고객 기본값을 덮어쓰지 않으며 기존 고객 레코드를 일괄 변경하지 않는다.
- 가입/소셜 가입의 모든 고객 필드, 이전 고객 기본값, 관리자가 별도로 지정한 값의 우선순위에 대한 회귀 검증을 추가했다.

| 관리자 접수 승인 | 제출본·첨부·승인 상태 | 제출 revision의 18개 값과 캠페인 source 자료의 18개 값이 일치. 프로젝트가 승인 revision을 참조. 고객 화면에서도 승인 상태 확인. |

고객 링크에서 입력한 캠페인 전용 담당자·제품명은 해당 캠페인의 접수본으로 보관된다. 고객·제품 마스터를 자동으로 덮어쓰지 않는 동작도 확인했다. 따라서 기본 업체 정보는 관리자 **고객·제품**, 캠페인 조건은 **프로젝트 → 자료 → 고객에게 필요한 정보 요청**에서 확인한다.
