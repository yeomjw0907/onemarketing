# 실사용 전 점검 — 2026-11-09

## 판정

코드 결함 수정과 격리 통합 검증은 완료했다. **유료 실거래 시작은 운영 준비를 마친 뒤에 해야 한다.** 운영 DB를 읽기 전용으로 재확인했을 때 결제 계좌가 미등록이고 `paymentReady=false`였다. 활성 참여자의 활동 계정 2개 중 소유 확인 완료는 0개였다. 공개 모집 캠페인도 없었다. 이를 임의 승인하거나 실제 계좌·입금 정보를 만들어 활성화하지 않았다.

내일 시작 전 운영자가 할 일:

1. `/admin/platform?tab=settings`에서 실제 수취 은행·계좌·예금주와 계좌이체 주문 받기를 설정한다. 고객에게 노출되는 수취 정보를 확인한다.
2. 활동 계정 소유자의 프로필 확인 문구 등 실제 증거를 확인한 다음 관리자에서 소유 확인을 처리한다. 가입 승인과 소유 확인은 별개다.
3. 실제 캠페인 내용·제공 내역·일정·광고 표기를 확인하고 실제 입금 확인 절차로 모집을 개시한다. 테스트 입금 확인으로 운영 캠페인을 열면 안 된다.
4. 카카오 실제 로그인은 사용자 인증 입력을 기다리는 상태다. 구글은 실제 제공자 인증과 앱 복귀까지 성공했으나 선택한 계정이 기존 광고주와 연결되지 않아 신규 가입 안내에서 중단했다. 실제 신규 회원 생성·약관 동의·실제 주문을 대신 수행하지 않았다.

## 수정한 결함

### MCP

- 설치된 공식 SDK의 Streamable HTTP Client로 광고주 서버에 실제 연결했다. 정상 인증 후 SDK가 보내는 선택적 GET/SSE 요청을 401로 응답해 재인증 오류가 2회 발생하는 문제를 재현했다. 유효 인증의 GET은 지원하지 않는 방식임을 나타내는 405로 응답하고 익명 요청의 401 인증 안내는 유지했다. 수정 후 SDK 오류 0건으로 초기화·도구 목록·호출·연결 종료를 통과했다.
- 광고주 MCP가 요청 크기 초과·속도 제한·DB 장애를 모두 400으로 바꾸던 문제를 수정했다. 413/429/503을 보존하고 429/DB 503에 재시도 헤더를 제공한다. DB 내부 정보는 응답에 노출하지 않는다.
- Origin이 있는 잘못된 출처 요청은 403, 정상 서비스/ChatGPT 출처 및 Origin 없는 네이티브 클라이언트는 기존 인증 절차를 적용한다. 기존 사용자·광고주 권한과 도구 범위는 확대하지 않았다.

### 참여자 가입 → 첫 지원

- 소유 확인 전 빈 활동 계정 선택창만 보이던 곳에 필요한 채널과 확인 요청 링크를 표시하고 제출을 막았다.
- 나의 활동에서도 소유 확인 필요를 안내한다. 문의 링크는 체험단·회원 정보 유형과 요청 목적을 미리 선택한다. 동의와 제출은 사용자가 수행한다.
- 문의 페이지 로그인 복귀 목적지가 사라지는 문제를 수정했다. 허용된 내부 경로만 보존하며 광고주/참여자 복귀 경로를 분리했다.
- 담당자 확인 후 전체 페이지를 다시 열지 않아도 ‘계정 확인 상태 다시 확인’으로 지원을 계속할 수 있다.
- 격리 서버의 실제 UI에서 문의 접수 → 관리자 확인/답변 → 상태 갱신 → 활동 계정 선택 → 지원 완료(신청 1명)를 확인했다. 운영 계정의 소유 확인을 대신 승인한 것은 아니다.
