# 업무 도우미 선택형 대화 검토

2026-10-20, `yeomjw0907/teacher` main 소스 기준.

## 확인한 구조

- `src/lib/agent/types.ts`: `single_select`, `multi_select`, `date_time`, `number`, `text`, `confirm` 질문을 구분하는 Zod 스키마. 직접 입력 허용 여부도 명시한다.
- `src/lib/agent/state-machine.ts`: 필요한 필드 중 누락된 첫 필드를 찾아 질문하고, 모두 채워지면 확인 단계로 전환한다.
- `src/components/work-conversation.tsx`: 단일 선택 버튼, 복수 선택 후 완료, 날짜 입력, 기타 직접 입력을 렌더링한다. 답변에 `questionId`를 붙여 어느 질문의 답인지 전달한다.

## 원케이션에 맞는 적용 범위

| 단계 | 입력 UI | 기준 |
| --- | --- | --- |
| 고객·제품 선택 | 검색 가능한 선택 목록 + 신규 등록 | 서버에서 현재 접근 가능한 실제 ID를 제공 |
| 콘텐츠 종류 | 블로그·클립 복수 선택 | 선택은 답변이며 발주·저장 동의가 아님 |
| 수량 | 채널별 숫자 입력 | 양의 정수·업무 한도 검증 |
| 게시 기간 | 시작일·마감일 | 기간 순서와 캠페인 일정 검증 |
| 상품·단가 | 등록 상품 선택 | 서버 가격 사용, 저장 직전 재검증 |
| 최종 저장 | 기존 확인 카드 | 사용자가 확인하고 저장한 경우만 MCP 쓰기 실행 |

이미 자연어로 받은 값은 다시 묻지 않는다. 필요한 질문 하나씩 보여주되 수량·기간처럼 연관된 필드는 함께 입력하게 한다. 항상 직접 입력할 수 있어야 한다. 과거 질문은 답변 완료 표시 후 비활성화하고, 서버는 질문 ID·대화 소유권·현재 단계·선택값을 검증한다.

## 재사용 판단

질문 스키마와 상태 기반 렌더링 패턴은 적합하다. 교사용 필드·선택지·문서 생성 API는 원케이션 도메인에 맞게 바꿔야 한다. 현재 업무 도우미의 모델 출력은 `reply`, `action`, `argumentsJson`뿐이므로 버튼 컴포넌트만 복사해서는 동작하지 않는다. 구조화된 질문 출력, 서버 검증·저장, PC 커넥터 출력 스키마, UI 답변 제출을 함께 확장해야 한다.

모델이 임의 실행 버튼이나 URL을 만들게 하지 않는다. 선택 가능한 고객·제품·상품은 서버 데이터로 한정한다. 계약 확정·카톡 발송은 현재와 같이 운영 화면에서 별도 확인한다.

이번 변경은 처리 중 Orb 표현 개선과 위 구조의 도입 가능성 검토다. 선택형 대화 엔진 자체는 아직 추가하지 않았다.
